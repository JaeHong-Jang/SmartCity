# ADR 0001: 실시간 협업 = 서버 순서 권위 Command 로그
- 상태: Accepted · 날짜: 2026-10-23 · 결정자: Opus (council: Astra, Argon)

## 맥락
여러 사용자가 같은 도시를 동시에 편집한다. 도로 그래프는 노드-세그먼트-신호-정류장 간 참조 무결성이 필수다.

## 결정
- 모든 변경은 `Command`, 적용은 `applyCommand()`(검증 + 언두 로그 롤백, batch 원자성).
- 서버가 수신 순서로 `seq` 부여 → 성공한 명령만 브로드캐스트. 실패는 보낸 사람에게 `rejected`.
- 클라이언트는 **비낙관적 적용**: 서버 에코 후 반영. 전송한 고스트는 `pending`(반투명 펄스)으로 유지, `applied` 시 실제 메쉬로 교체, `rejected` 시 붉은 플래시 + 토스트.
- 오래된 계획(이미 분할된 세그먼트 참조 등)은 batch 전체가 거부되고 클라이언트가 재계산한다.
- ID: 서버가 세션마다 고유 `tag` 발급 → `IdGen(tag)`. 재접속 시 새 tag.
- **일관성 복구**: `welcome`(doc + seq)과 이후 `applied`는 같은 이벤트 루프에서 순서 보장. 클라이언트는 `seq ≤ 현재 seq` 무시, `seq > 현재+1`(누락) 감지 시 재접속하여 전체 스냅샷 재수신. 끊긴 동안의 pending 명령은 결과 불명으로 폐기하고 사용자에게 알림.
- 서버 없을 때 `LocalTransport`(브라우저 내 시퀀서 + localStorage)로 단독 모드.

## 고려했으나 기각
- CRDT(Yjs/Automerge): 병합 결과가 그래프 불변식을 보장 못함. (프레즌스 전용으로도 불필요 — 자체 채널 사용)
- 낙관적 적용 + 롤백: 분할을 포함한 batch의 롤백·재적용 복잡도. Phase 2에서 재검토.

## council 의견 요약
Astra: 재접속·중복·스냅샷 경계 계약 필요(blocker) → 위 "일관성 복구"로 반영. Argon: pending 고스트 상태 머신 필수 → 반영.
