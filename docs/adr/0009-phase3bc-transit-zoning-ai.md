## 결정

### 1. 문서 v4 (shared)
- **선택 필드 추가:**
  - `VehicleType.capacity?`(1–200)
  - `IntersectionControl.scramble?`
  - `Parcel.auto?`, `Parcel.frontage?: {segmentId, side: 'left' | 'right'}`
  - `Building.auto?`
  - `BuildingType.growth?: {level: 1}`
  - `CityMeta.growth?: boolean`(생략 = 켜짐)
- **필드 보존:** 모든 clean·복사 경로(`building.place`, `parcel.upsert`, `cleanVehicleType`, `cleanControl`, 설계 upsert)가 새 필드를 보존하는지 **왕복 테스트**로 확인한다.
- **성장용 기본 설계 6종**(주거·상업·업무 × 소·중, level 1)은 `createEmptyDoc`과 **v3→v4 마이그레이션에서만** 추가한다. 사용자가 지운 설계가 되살아나지 않게 하기 위해서다.
- `validateParcel`은 AABB 사전 필터 뒤에 다각형 교차를 검사한다.

### 2. 버스 승객 (sim)
- **소유권:** 시민은 정확히 한 곳에 속한다.
  - 소속은 보행자, 정류장 대기열 `(stop, line)`, 버스 `riders`, 하차 대기 `alighting` 중 하나다. 정류장 대기는 별도 상태다.
  - 모든 종료 경로는 각각 정확히 한 번 정리한다.
  - 불변식 테스트는 상태 합계와 중복·고아 참조 0을 함께 검사한다.
- **정류장 노드:** PedGraph가 정류장 진행 방향 쪽 보도에 정류장 노드를 둔다. 보도가 없는 정류장은 승객 서비스를 하지 않는다.
- **도착 처리:** 버스가 정류장에 도착하는 틱에 한 번 처리한다.
  - 버스 처리 순서는 차량 id 순이다.
  - 하차자는 riders에서 `alighting`으로 옮긴다.
  - 승차 인원은 `board = min(대기열, max(0, capacity − 남는 탑승자), 20)`이다. 정원이 줄어 기존 탑승자가 정원을 넘으면 내릴 때까지 태우고, 새로 태우지 않는다.
  - 대기열은 FIFO이며 순서는 `(도착 tick, personId)`다.
  - 정차 시간은 `dwell = clamp(10 + max(alight·1.0, board·1.5), 10, 40) s`다. 상한 20명은 dwell 상한과 맞춘 값이다.
  - dwell이 끝나는 틱에 `alighting` 승객이 보행자로 생성된다.
- **대기 한도:** 게임 30분(물리 180초)을 넘기면 대기를 포기하고 걸어간다. 이벤트 seq 가드로 처리하고, 승차하면 대기 이벤트를 무효화한다.
- **정리 경로:**
  - 버스가 제거되면 riders와 `alighting` 승객은 `failTrip`(도착 처리, 집계)한다.
  - 노선에서 하차 정류장이 빠지면 다음 정류장에서 내려 걷는다.
  - 정류장이 삭제되거나 보도가 사라지면 대기자는 걸어간다.
  - 노선이 삭제되면 대기자는 걸어가고 탑승자는 `failTrip`한다.
  - 집이 철거되면 기존 규칙을 따르되 위 모든 관계에서 정리한다.
- **수단 선택:** **명시적 분기**다.
  - 직행 버스 후보가 없으면 기존 규칙(1km, 자가용 보유)과 정확히 같은 결과를 낸다.
  - 후보가 있으면 도보·버스·자가용의 예상 시간에 시민별 해시 편향(±15%)을 곱해 비교한다.
  - 버스 시간 = 정류장까지 도보 + 배차 반 간격 + 승하차 사이 유향 경로 길이/8 + 중간 정류장×15 + 하차 후 도보다. 대수가 0이거나 폐쇄로 끊긴 노선은 제외한다.
  - 후보 캐시는 네트워크 재컴파일과 파생 상태(정류장·노선·차종) 갱신 때 모두 무효화한다.
- **스냅샷:**
  - `busLoad`(Uint16, 차량 순서)를 둔다. `SnapshotBuffers`와 `snapshotTransferables`에 포함한다.
  - 정류장 대기 보행자(state=busStop)는 대기 순번으로 보도 방향 0.65m 간격 2열 오프셋을 받아 겹치지 않는다.

### 3. 보행 전용 위상 (sim + shared + web)
- **적용 조건:** `scramble: true`는 `kind = 'signal'`, 차수 3–4, 횡단보도 있는 다리 ≥ 2일 때만 유효하다. 이후 도로·보도 편집으로 조건이 깨지면 컴파일 시 무시한다.
- **위상 구성:** 차량 위상 뒤에 보행 전용 위상을 붙인다.
  - 이 위상에서 차량은 전적색이고 yellow는 0이다.
  - 모든 다리 횡단보도가 WALK 7s 후 CLEARANCE에 들어간다. 길이는 `7 + ⌈최장 횡단 / 1.0⌉`이다.
  - 차량 위상에서는 보행 WALK가 없다(독점).
- **안전:** 기존 원자 예약을 그대로 쓴다. 차량 위상 시작 시 남은 보행자가 있으면 차량은 계속 막힌다.
- **UI:**
  - 인스펙터에 체크박스와 총 주기(초)를 표시한다.
  - 렌더 서명(`controlSig`)에 scramble을 포함한다.
  - 모든 방향 보행등이 동시에 켜지는 것이 보이게 한다.

### 4. 조닝·자동 성장 (shared + server + web)
- **조닝 도구:** 순수 함수 `lotsAlongSegment(doc, segId, side, t0, t1, depthCells, zone)`가 lot 목록을 만든다.
  - 8m 셀, 깊이 1–4, 폭 16–24m 직사각형이다.
  - 교차로 setback과 횡단 구역은 제외한다. 겹치는 lot은 생략한다.
  - 각 lot은 `frontage`를 저장한다.
- **도구 입력:**
  - 도로 위에서 드래그해 칠한다. 좌우 면은 커서 위치로 정한다.
  - 깊이는 `[`/`]` 키와 옵션 패널 버튼으로 바꾼다. 숫자키와 휠은 기존 기능과 충돌하므로 쓰지 않는다.
  - 지우기 모드가 있다.
  - 칠한 결과를 `parcel.upsert` batch 한 명령으로 보낸다.
- **도로 편집과 auto 필지:**
  - 같은 트랜잭션에서 새 차도 띠와 겹치는 auto 필지를 제거한다. 그 안의 auto 건물도 함께 제거한다. 사용자 건물은 기존 충돌 규칙을 따른다.
  - frontage 세그먼트가 삭제되거나 분할되면 auto 필지는 성장 대상에서 빠진다. 분할 시 `frontage.segmentId`는 해당 쪽 자식으로 재매핑한다.
  - 도로 프리뷰는 제거될 auto 필지와 건물을 적색으로 표시한다.
- **성장 실행:** 서버와 `LocalTransport`가 공통 `growthTick`을 쓴다. 이 함수는 shared의 순수 `growthStep(doc, epoch)` 위에 있다.
  - 5초(벽시계)마다 실행한다. 룸에 접속자가 없거나 `meta.growth === false`면 건너뛴다. HUD에 일시정지 토글을 둔다.
  - 한 번에 최대 4개의 **독립 작업 단위**를 만든다. 각 단위는 복제 문서에서 검증하고, 성공한 것만 평탄한 batch 하나로 묶는다.
  - 커밋은 `Room`의 공통 커밋 함수(검증·로그·롤백·seq·브로드캐스트)를 사용자 명령과 함께 쓴다. `by: 'system'`이다.
- **수요:** `designStats`와 같은 양(인구·일자리)을 쓴다. 계산은 별도로 하며, 필지 전수 검사 비용을 피하기 위해서다. 산업 성장은 MVP 미지원으로 표시한다.
  - 시험 플레이로 조정했다(2026-10-23, `harness/runs/3b/grow-sim.ts`). 조사 09의 분모 하한 100, 임계 0.1로는 아파트 몇 채 뒤에 모든 수요가 0.1 아래로 떨어져 성장이 멈췄다.
  - 그래서 분모 하한을 30으로, 성장 임계를 0.05로 낮추고, 주거 기본 유입 +0.15를 더했다. 부트스트랩 0.2는 빈 도시에만 적용한다.
  - 결과: 5×5 격자를 전부 조닝하면 50틱 안에 주거 128·상업 18·업무 11채가 자란다. 이후에는 주거 필지가 소진되고 주거 수요(약 0.17)만 남는다. 사용자가 조닝을 더 칠하면 다시 자란다.
- **배치:** 후보 설계의 실제 footprint를 lot 안에 넣는다.
  - 위치는 앞면 중앙에서 setback과 footprint 돌출량만큼 안쪽이고, 회전은 도로를 향한다.
  - 후보 건물을 넣은 문서에서 `parcelCompliance` 위반이 0일 때만 배치한다. 결과에 `Building.auto`를 붙인다.
  - 사용자가 auto 건물을 이동·회전·교체하면 `auto`가 해제된다. 인스펙터에 "자동 관리 해제" 토글을 둔다.
- **렌더:** auto 필지는 면과 테두리 메쉬만 그린다. 라벨은 선택·호버·위반이 있을 때만 붙인다. 조닝 도구 사용 중에는 lot 미리보기를 보여 준다.

### 5. AI 건설 도우미 (server + web)
- **SDK와 모델:**
  - `@anthropic-ai/sdk`를 쓴다. 키는 서버 `ANTHROPIC_API_KEY`(`apps/server/.env`, gitignore)에 둔다.
  - 모델은 `SC_AI_MODEL`이고 기본값은 사용자가 고른 `claude-sonnet-5-5`다. adaptive thinking, effort `medium`, 서버측 fallbacks `"default"`를 쓴다.
  - 키가 없으면 비활성이다.
- **흐름:**
  - 서버의 수동 도구 루프가 룸 문서의 **샌드박스 복제본**에서 제안을 만든다. 제안은 요청자에게만 보낸다.
  - 사용자가 다중 고스트 미리보기(`ProposalLayer`: 제안 속 신규 설계를 임시로 굽고, 설계별 인스턴싱)를 보고 승인하면 **사용자 명의의 일반 `cmd` batch**로 적용한다. 출처 메타데이터는 `ai`다.
- **명령 범위:** MVP 제안은 **추가만** 한다. 신규 설계(새 id), 건물 배치(새 id), auto 조닝 필지가 전부다. 철거와 도로 변경이 없으므로 "유효하지만 낡은 제안"이 기존 대상을 파괴하지 않는다.
- **충돌 처리:** 문서가 바뀌면 클라이언트가 제안을 항목별로 드라이런하고 충돌 항목을 주황색으로 표시한다. 버튼은 "가능한 항목만 적용(N/M)"과 "다시 요청" 두 가지다.
- **도구:**
  - `get_city_overview`
  - `find_spots`: 개수와 크기를 탐색 전에 제한한다.
  - `create_building_design`: 블록 입력 `{blocks:[{x,y,z,w,d,h,color,roof?}]}`을 `voxelsToParts`로 변환한다. 프리셋 변형도 허용한다.
  - `place_buildings`
  - `zone_along_road`
  - `finish`
  - 서버가 모든 입력을 다시 검증한다.
- **비용·남용 상한:**
  - 서버 전체: 동시 실행 2, 시간당 요청 상한 `SC_AI_MAX_PER_HOUR`(기본 60)
  - IP당: 10분에 10건, 룸당 동시 1건
  - 요청당: 반복 10회, 누적 입력 토큰 200k, 누적 출력 토큰 40k, 실행 120초, 도구 결과 8KB, 제안 명령 200개
  - `ai.cancel`, 연결 종료, 룸 폐기 시에는 AbortController로 외부 호출을 취소하고 슬롯을 해제한다. 늦게 온 응답은 버린다.
- **보안:** 문서 문자열은 데이터로만 취급한다(system에 명시). 로그에는 요청 텍스트 길이, 모델, 토큰 사용량만 남긴다.
- **테스트:**
  - `AiClient`를 주입해 각본 모델로 단위 테스트를 한다.
  - `SC_AI_FAKE=1`로 e2e 흐름(요청 → 미리보기 → 적용 → 다른 클라이언트 반영)을 확인한다.
  - 실제 API 호출은 키가 있을 때만 수동으로 확인한다.

## 고려했으나 기각한 대안
- **클라이언트 sim이 성장을 수행:** 불변식 1·3을 위반한다.
- **AI가 system 명의로 직접 적용:** 승인과 책임이 불명확하다.
- **전역 `baseSeq` 전제조건:** 5초 성장 때문에 제안이 계속 무효가 된다. 대신 추가 전용 제안과 항목별 드라이런을 쓴다.
- **필지 셀 저장:** 셀 수가 폭발한다.
- **스크램블 병행 모드:** 결과 예측이 어렵다.

## 결과
- **좋은 점:**
  - 버스가 실제로 사람을 태운다.
  - 교차로에서 모든 방향 보행이 동시에 열린다.
  - 도로를 칠하면 도시가 스스로 자란다.
  - 말로 건물을 설계하고 배치할 수 있다.
  - 모든 변경이 명령 로그로 남는다.
- **감수할 점:**
  - 대각선 횡단과 레벨업은 다음 단계다.
  - 성장 시점은 벽시계라 초기 문서만으로는 미래 성장을 재현할 수 없다. 로그로는 재현된다.
  - 버스 시간 추정은 정체를 반영하지 않는다.
  - 3b는 의도된 동작 변경이라 골든 트레이스를 사유와 함께 재기록한다. 재기록 전에 "노선·스크램블·auto 필지 없는 문서는 3a와 해시 동일" 회귀 테스트를 통과해야 한다.

  - B1(렌더 서명): 대각선은 미루고 scramble을 `controlSig`에 넣는다.
  - B2: `ProposalLayer`로 반영했다.
  - B3: LocalTransport 성장과 일시정지 토글로 반영했다.
  - B4: AABB 필터와 auto 라벨 생략으로 반영했다.
  - M1: 정류장 줄 서기 오프셋으로 반영했다.
  - M2: busLoad를 transferable로 넣고 창문 대신 배지로 표시한다.
  - M3·m1: 스크램블 UI, 철거 예고, 자동 관리 해제로 반영했다.
