# ADR 0011: 서버 연결 실패 시 자동 오프라인 금지 + 체크포인트 안전장치
- 상태: Accepted
- 날짜: 2026-10-25
- 결정자: Opus

## 맥락
`?room=main`을 열었는데 도시가 "전부 사라진" 사고. 서버의 `main.json`은 멀쩡했다. 웹이 서버 소켓을 1.5초 안에 열지 못하면(개발 서버 재시작 중 새로고침) **같은 room 이름**으로 `LocalTransport`(`localStorage` `smartcity:local:<room>`)를 자동으로 열어, 예전에 브라우저에 저장된 다른 도시가 토스트 한 줄과 함께 떴다. 그 상태의 편집은 서버가 아닌 브라우저에만 저장됐다.
서버 쪽에도 체크포인트 파싱 실패 시 "로그만 재생"(로그는 체크포인트마다 비워지므로 사실상 빈 도시)으로 시작해, 다음 체크포인트가 원본을 덮어쓸 수 있는 경로가 있었다. ADR 0001의 "서버 없을 때 단독 모드"와 ADR 0002의 로드 규칙을 아래로 대체한다.

## 결정
- **자동 오프라인 전환 없음.** 서버 room은 첫 welcome 전까지 전체 화면 오버레이("서버에 연결하는 중… (n번째 시도, 다음 시도 m초 후)")를 띄우고 지수 백오프(0.5 s → 최대 10 s)로 재시도한다. 백오프·시도 횟수는 소켓 open이 아니라 **welcome**에서 초기화(열고 거부하는 서버를 0.5 s마다 두드리지 않음). 페이지가 바빠 타이머가 늦게 울린 경우 재무장하는 기존 로직은 오버레이 표시 시점에만 쓴다. 서버가 room을 거부하면(`error`) 그 문구를 오버레이에 표시한다. 각 시도에는 welcome 기한이 있어, 열린 채 침묵하는 소켓도 끊고 같은 백오프로 재시도한다. 기한은 10 s에서 시작해 기한 초과가 이어질 때마다 두 배(최대 60 s, welcome에서 초기화)로 늘어 매번 느린 서버도 결국 연결되고, 현재 소켓에서 메시지가 오면 다시 시작한다(바이트 단위 진행은 브라우저 WebSocket에서 관찰할 수 없음). 늦게 울린 기한 타이머는 재무장. 끊은 소켓의 늦은 이벤트는 세대 번호로 무시한다.
- **오프라인 단독 모드는 명시적으로만**: 오버레이 버튼 또는 `?offline=1`(둘 다 URL 이동). 저장 키는 `smartcity:offline:<room>`으로 분리, 상단에 사라지지 않는 붉은 배너와 [서버에 다시 연결].
- **읽을 수 없는 저장본 ≠ 저장본 없음**: 오프라인 저장본이 손상·형식 불일치·구조 검사 실패·더 새로운 버전이면 빈 도시로 열지 않는다. 오류 화면에 사유와 [원본 내보내기](원문 그대로)만 제공하고, `LocalTransport`는 그 키에 저장하지 않으며 편집을 거부한다. 온라인 알림도 "읽을 수 없음"으로 표시한다.
- **이전 키 마이그레이션**: 새 키가 없고 `smartcity:local:<room>`이 있으면 원문을 새 키로 **복사**한다. 원본 키는 지우지도 쓰지도 않는다(안전 우선 — 사용자가 직접 지울 때까지 보존). 이후 편집은 새 키에만 저장된다.
- **온라인 접속 시 알림**: 이 브라우저에 같은 이름의 오프라인 도시(새 키 우선, 없으면 이전 키)가 있고 비어 있지 않으며 서버 doc과 JSON이 다르면 비차단 알림(건물·도로 수, 마지막 수정 시각, [열기] [JSON 내보내기] [닫기]). 자동 병합 없음. [닫기]는 그 저장본(`seq:savedAt`)을 이 탭(sessionStorage)에서만 기억한다.
- **재연결(이미 ready였던 세션)**: 기존처럼 `reconnecting`(편집 차단) + 상단 노란 배너. 오프라인으로 바뀌지 않는다.
- **서버 로드 거부**: 체크포인트가 파싱·형식 검사·마이그레이션·구조 검사(`shared/docCheck.ts`의 `docProblem` — 컬렉션은 배열이 아닌 키 객체, 엔티티 id = 키, 필수 필드, 핵심 참조)에 실패하면 그 room을 거부하고 원본은 그대로 둔 채 `<room>.corrupt-<파일 수정 시각>.json` 사본을 1회 남긴다. 원본을 옮기지 않는 이유: 옮기면 다음 접속이 빈 도시로 시작해 덮어쓰기 경로가 되살아난다. `doc.version > DOC_VERSION`도 거부. 명령 로그도 엄격히 재생한다: 레코드 형식 오류·빈 줄·seq 역행/중복/건너뜀·재생 실패는 `LogCorruptedError`로 room을 거부하고 로그를 그대로 둔다(예전엔 건너뛰고 열어, 다음 체크포인트가 로그를 비웠다). 줄바꿈 없는 마지막 레코드(쓰기 중단)만 잘라내고 연다. 로그 레코드는 이미 시퀀서가 승인한 명령이므로 `trusted` 모드로 재생하고, `trusted`는 정책 검사와 함께 **컬렉션 용량 한도도 건너뛴다**(마이그레이션이 프리셋을 추가해 한도를 넘긴 문서에서도 그 이전에 승인된 로그가 재생되도록; 같은 모드를 쓰는 클라이언트 `applied`와 sim도 서버가 승인한 명령이므로 동일). 구조 검증(알 수 없는 명령, 잘못된 형태)은 그대로라 손상 레코드는 여전히 거부된다. 새 편집(비신뢰)의 용량 한도는 그대로 적용된다. 현재 마이그레이션이 추가하는 것은 건물 설계(성장·시설 프리셋)뿐이다.
- **백업**: 체크포인트 직전 기존 파일을 `backups/<room>/<UTC ISO, ':'→'-'>[-n].json`으로 배타적 복사(같은 밀리초면 다음 접미사, 덮어쓰기 없음; 직전 백업과 같으면 생략), 최근 30개 + 14일간 UTC 날짜별 1개 보존. 실패해도 체크포인트는 진행. 건물+도로 10 이상이던 도시가 0이 되는 체크포인트는 경고 로그 + `.prewipe` 백업(14일 보존)을 남기고 쓰기는 진행(정상 철거일 수 있음).

## 고려했으나 기각한 대안
- 오프라인 도시를 서버 doc에 자동 병합: 그래프 불변식·ID 충돌을 보장 못함(ADR 0001 CRDT 기각과 같은 이유). 내보내기 → 가져오기(새 방)로 대체.
- 마이그레이션 후 이전 키 삭제: 실패·다중 탭 경합 시 유일한 사본을 잃을 수 있어 기각.
- 손상 체크포인트 자동 복구(최신 백업으로 대체): 어떤 백업이 맞는지는 사람이 판단해야 함. 거부 + 문서화된 수동 복구.

## 결과 (좋은 점 / 감수할 점)
- 서버 도시와 브라우저 도시를 혼동할 경로가 사라지고, 서버 파일이 빈 도시로 덮일 경로가 막힌다.
- 서버가 없으면 기다리거나 명시적으로 오프라인을 골라야 한다(예전엔 자동). 이전 키는 수동으로 지울 때까지 남는다.
- 백업은 `data/backups/`에 쌓인다(룸당 최대 약 30 + 14 + prewipe 개).
