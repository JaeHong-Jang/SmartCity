# ADR 0012: Phase 5 — 부드러운 건설 (도로 모서리·그리기·건물 배치·곡면 건물)

- 상태: Accepted · 날짜: 2026-10-25 · 결정자: Opus (council: Astra, Sol — Argon 사용량 한도로 불참)
- 제안서: `harness/runs/p5/proposal.md` · council 원문: `harness/runs/p5/{astra,sol}.md` (둘 다 조건부 동의·계약 수정 요구)
- 조사: [12 부드러운 도로·곡면 건물](../research/12-smooth-roads-curved-buildings.md)

## 맥락
사용자가 4가지를 모두 요청했다.
1. 도로 모서리를 둥글게. 꺾인 곳이 뾰족한 쐐기로 보인다.
2. 도로 그리기 조작을 부드럽게.
3. 건물 배치·편집을 부드럽게.
4. 건물 모양 자체를 곡면으로.

뾰족해 보이는 원인은 차수 2 노드의 접합 폴리곤이다. 세그먼트에는 이미 2차 베지어 `control`이 있다. 건물 파트는 직사각형이거나 직교 footprint만 허용한다.

## 결정

### 1. 도로 필렛: 문서에 굽기
- **표현 방식**
  - 꺾인 지점 V에서 양쪽으로 T만큼 물러난 두 점을 새 노드로 만든다.
  - 두 노드 사이는 제어점이 V인 2차 베지어 세그먼트로 잇는다.
  - 기존 `control` 필드만 쓰므로 스키마는 변경 없다.
  - 문서가 진실이고, 시뮬 차선은 이 곡선을 따른다.
- **반경 = 실제 최소 곡률반경** (council 공통 지적)
  - 대칭 2차 베지어의 최소 곡률반경은 ρ_min = T·cos²(δ/2)/sin(δ/2)이다. 원호 식 T = R·tan(δ/2)를 쓰면 90°에서 실제 반경이 R/√2로 작아진다.
  - 그래서 필요한 T = ρ_req·sin(δ/2)/cos²(δ/2)로 계산한다.
  - **기하 하한** ρ_floor = 도로 반폭 + 4 m. 안쪽 오프셋이 접히지 않게 하는 값이다. 도로 타입마다 선호 반경이 있고 기본값은 max(하한, 타입 선호)다.
  - 공간이 모자라면 선호 반경에서 하한까지만 줄인다. **하한 아래로는 줄이지 않는다.** 하한도 불가하면 꺾임을 그대로 두고 이유를 표시한다.
- **길이 예산**
  - 같은 원본 세그먼트 양끝에 필렛이 붙으면 T_left + T_right + L_reserve ≤ L을 함께 검증한다.
  - 남는 직선과 새 곡선은 각각 `minSegmentLength`(8 m, 곡선은 호 길이) 이상이어야 한다.
  - 반대쪽 끝이 차수 3 이상 교차로면 그 접합부가 쓰는 길이를 예약한다.
- **거절 조건**
  - δ < 10°는 필렛 없이 그대로 둔다.
  - δ > 150°(거의 되돌림), 영 길이, 중복점, 비유한 수치는 거절한다.
- **초기 적용 범위** (council 블로커 — 참조 이전)
  - 대상은 직선 두 개, 같은 도로 타입·단면, 차수 2 노드다.
  - 영향 구간(물러나는 길이 안)에 정류장·노선 경유·폐쇄·frontage 필지·구간 횡단보도·노드 교차로 설정이 **없어야** 한다.
  - 하나라도 있으면 거절하고 이유를 표시한다. 참조 이전은 후속 과제다.
- **명령과 동시 편집**
  - 새 명령 `road.fillet { nodeId, radius, ids }`를 쓴다. 기하는 `applyCommand` 안에서 현재 문서로 결정적으로 계산한다.
  - 서버 순서 처리 시점에 전제조건을 **재검증**한다: 노드 존재, 차수 2, 두 세그먼트 직선, 같은 타입, 참조 없음, 길이 예산. 실패하면 전체를 거절한다.
  - 새 id는 payload에 둔다.
  - 클라이언트가 만든 오래된 batch를 그대로 적용하지 않는다.
- **새로 그리는 도로의 자동 필렛**
  - 그리기 플래너가 꺾임마다 곡선을 직접 포함해 계획한다. 새 도로에는 참조가 없다.
  - 기본은 켜짐이고 끌 수 있다.
  - 기존 도시는 자동으로 바꾸지 않는다. 기존 꺾임은 사용자가 선택해서 "모서리 둥글게"를 실행한다(선택 노드마다 `road.fillet`).
- **골든**
  - "필렛을 적용하지 않은 문서는 컴파일·골든이 그대로다."
  - 필렛 문서는 새 그래프 기대값으로 검증한다(차선이 곡선을 따름, 커넥터, 차수 2 새 노드의 연결 동작).
- **차수 3 이상 교차로의 연석 모서리 둥글게**
  - 렌더 전용이다.
  - 차도 주행 영역·정지선·횡단보도는 바꾸지 않는다. 바꾸게 되면 이 결정의 범위 밖이다.

### 2. 그리기 조작 (단계 분리)
- **b1: 직선 조작감**
  - 소프트(자석) 스냅을 쓴다. 진입·이탈 거리는 화면 픽셀 기준이고 히스테리시스를 둔다.
  - 후보 우선순위: 도로 끝점 > 도로 내부 > 각도(15°) > 격자. 동률은 결정적으로 처리한다.
  - 각도 가이드선과 길이를 표시한다.
  - 미리보기와 확정은 같은 플래너 결과를 쓴다.
- **b2: 곡선**
  - 기존 도로 끝에서 시작하면 접선은 곡선 끝점의 미분 방향이다.
  - 제어점 기본값은 접선 위 현 길이의 1/2 지점이고, 드래그 핸들로 조정한다.
  - 빈 공간에서 시작하면 3클릭(시작, 제어, 끝) 또는 드래그 핸들을 쓴다.
- **b3: 자유 그리기**
  - 드래그 → RDP → 2차 B-스플라인 순서다. 교차점과 끝점은 보존한다.
  - **최종 곡선**을 대상으로 충돌·자기교차·최소 길이·실제 곡률을 검사한다. 실패하면 자동으로 왜곡하지 말고 미리보기에서 거절한다.
- **종료와 전송**
  - 종료는 Enter, 더블클릭(마지막 점 중복 없음), 완료 버튼으로 한다. Esc는 취소다. 우클릭만으로 종료하는 방식은 쓰지 않는다(트랙패드).
  - 전송하는 것은 확정된 좌표·제어점·id다. 결정론의 기준은 명령이다.

### 3. 건물 배치·편집
- **세 자세를 분리한다**
  - **목표 자세**: 입력과 스냅의 결과다. 권위 있는 값으로, 충돌·색·명령에 쓴다.
  - **고스트 표시 자세**: 렌더 전용 임계감쇠 스프링으로 보간한다. 회전은 최단 경로로, 프레임 간격에 안정적으로.
  - **확정 자세**: 클릭할 때의 목표 자세다. 클릭하면 고스트를 목표로 즉시 맞춘다.
- **도로 정렬**
  - 도로 선택에 히스테리시스와 잠금을 둔다. 잠금은 수동으로 풀 수 있다.
  - 곡선 도로에서는 **호 길이** 기준으로 건물 폭 구간의 할선 정렬을 한다. 할선 정렬은 회전 후보를 만드는 데만 쓴다.
  - 확정 여부는 건물 전체 외곽과 도로 영역의 간격 검사로 결정한다.
  - 협업 편집으로 선택한 도로가 사라지면 후보를 무효화한다.
- **회전**
  - **T**를 누른 채 마우스를 움직이면 연속 회전한다(구현 시 변경: R은 카메라 줌아웃 키라 충돌). T를 짧게 누르면 +15°. 기존 키(`,` `.` 15°, Shift 자유 배치)는 유지하고, L은 도로 잠금/해제다.
  - 숫자 입력 대안을 둔다. 각도 스냅은 끌 수 있다.
  - 키 반복·포커스 상실·취소 시 상태를 초기화한다.

### 4. 곡면 건물
- **`BuildingPart.round?: number`**
  - 의미는 **둥근 직사각형** 모서리 반경(m)이다.
  - 범위는 0 ≤ round ≤ min(폭, 깊이)/2다. 최대값이면 정사각형은 원, 아니면 **캡슐**이다. 타원이 아니다.
  - `footprint`와 함께 쓸 수 없다(거절). 첫 버전은 flat roof만 지원한다. dome/cone 지붕, 타원, 오목 footprint 둥글림은 후속이다.
  - 생략, 0, null은 기존 결과와 완전히 같다. 음수·초과·비유한 수치는 거절한다.
- **`partOutline()`**
  - shared의 순수 함수로 둔다. 충돌·면적·선택·고스트·메시가 공통으로 쓴다.
  - 정점 순서·시작점·중복점 제거·정밀도를 고정한다.
  - 호 분할 수는 지원하는 최대 크기와 허용 오차로 정하는 결정적 상수 테이블에서 가져온다. 카메라나 LOD에 의존하지 않는다.
  - 면적은 근사 다각형 기준으로 통일한다.
- **파사드**
  - 연속 곡면 run 안에서 u = 누적 호 길이로 둔다.
  - 법선 평균은 곡면 run 안에서만 한다. 지붕·바닥 경계와 의도한 모서리는 날카롭게 유지한다.
- **스튜디오**
  - 직사각형 파트 단위로 둥글기를 정한다(볼륨 선택 → 반경 슬라이더).
  - 복셀 연결 성분 전체를 둥글리는 것은 후속이다(틈 위험).
- **AI**
  - 블록에 `corner_radius`(nullable)를 둔다. null과 누락은 생략으로 정규화하고 서버 공통 검증을 거친다.
- **버전** (council 블로커)
  - DOC_VERSION을 7로 올린다. v6→v7은 형상을 보존한다.
  - `PROTOCOL_VERSION`도 2로 올린다. 서버는 hello에서 프로토콜 버전이 다른 클라이언트를 받지 않는다(기존 검사 재사용). 그래서 구버전 클라이언트가 편집에 참여할 수 없다.
  - 서버의 검증·저장·복원 경로도 새 필드를 처리한다.

## 순서
1. **P5c 배치·편집**과 **P5a 필렛 최소 범위**를 병렬로 진행한다. P5a는 수동 "모서리 둥글게"와 새로 그리는 도로의 자동 필렛이다.
2. P5b를 b1 → b2 → b3 순으로 진행한다.
3. P5d 곡면 건물: 버전·프로토콜 → 직사각형 round·flat → 스튜디오·AI 순이다.

## 고려했으나 기각
| 제안 | 기각 이유 |
|---|---|
| 컴파일 시 필렛 파생 | 기존 도시가 자동으로 바뀌고 골든·차선이 바뀐다. 문서와 화면도 불일치한다 |
| 렌더 전용 필렛 | 시뮬 차선과 화면이 어긋난다 |
| 원호 반경 식 그대로 사용 | 실제 곡률이 의도보다 급하다(90°에서 R/√2) |
| 공간 부족 시 하한 아래로 축소 | 안전 하한이 무력화된다 |
| 클라이언트 batch로 필렛 | 계획 이후 동시 편집으로 전제가 깨져도 적용될 수 있다 |
| 단일 스칼라로 타원까지 표현 | 둥근 직사각형의 최대값은 캡슐이다. 의미가 혼동된다 |
| DOC_VERSION만 올림 | 진행 중인 협업에서 구버전 클라이언트를 막지 못한다 |
