# ADR 0013: Phase 6 — CCTV·센서 감지, 실제 도시 같은 외관·성능

- 상태: Accepted · 날짜: 2026-10-29 · 결정자: Opus (council: Astra, Argon — 둘 다 approve-with-changes)
- 제안서: `harness/runs/p6/proposal.md` · council 원문: `harness/runs/p6/{astra,argon}.md`
- 조사: [13 실제 도시 같은 외관](../research/13-realistic-city-look.md), [14 CCTV·센서](../research/14-cctv-sensors-sim.md)

## 맥락
사용자 요청: CCTV·센서를 도시에 설치하고 시뮬레이션과 연동(선택: "배치 + 시뮬레이션 연동"), 그리고 "미니어처가 아닌 실제 도시 같은 외관"을 렉 없이. 팀 보고서의 AI City 구조에서 센서는 "눈"이다.

## 결정

### 1. 감지 모드 — 세 의미를 분리 (council blocker)
| 모드(`policy.detection`) | 인지 시점 | 용도 |
|---|---|---|
| `legacy`(생략 시 기본) | 사건 발생 tick | 기존 기록·골든 호환(바이트 동일한 sim 결과) |
| `reports` | 시민 신고 tick | 센서 미사용 기준군 |
| `sensors` | min(시민 신고, 유효한 각 센서 감지) | 센서 사용 실험군 |
- 센서 개수가 모드를 정하지 않는다. `sensors` + 센서 0개 = `reports`와 같아야 한다.
- 비교는 항상 2회(A vs B): 프리셋 ① 스마트 대응 OFF vs ON(기존), ② 감지 `reports` vs `sensors`. 한 번에 조건 하나.
- 대상 사건: **사고·화재만**. 운영자 도로 통제·수요 급증·정전·응급(환자)은 감지 지연 없음(이미 알려진 조치/별도 경로).

### 2. 물리 상태와 인지 상태 분리 (council blocker)
- 사고 장애물·화재 진행·정전 등 물리 효과는 발생 tick부터.
- 현장에서 막힌 차로를 직접 만난 차량의 복구 탐색(`bannedRequest`)은 즉시(현장 목격).
- 관제가 아는 사고 비용(라우터의 사고 패널티·진입 금지)과 정보 수신 차량의 원거리 우회 알림(`enqueueAffected`), 출동은 **인지 tick부터**. 라우터는 물리 배열과 "알려진 비용" 배열을 분리한다(같은 라우터 공유 가능). `legacy`는 둘을 같게 취급해 기존과 동일.
- **인지 전 정보 경계(P6b-1 리뷰 반영)**: 인지 전에도 경로 탐색은 실시간 혼잡(차선별 정지 차량 수 `w.stopped`·속도)을 일반 교통정보처럼 본다 — 내비게이션이 원인을 모른 채 프로브 데이터로 정체를 피하는 것과 같다. 사건 자체는 보지 않는다: 사고 패널티·진입 금지·방송 우회·출동은 인지 전에 없다. 현장 복구는 그 사고를 직접 본 차량(시야 40 m)에 한정한 차량별 처리다 — 막힌 차선에서 멈춘 차량은 같은 방향 인접 차선으로 옮기고(공간·경로가 있을 때), 그 차선에 들어가기 직전 차량은 그 탐색 한 번에만 사고 패널티를 둔 재탐색을 한다. 공유 라우터에는 공개하지 않으며, 인지 후에도 이미 막힌 차선 위 차량은 같은 방식으로 처리한다. `legacy`에는 적용하지 않는다(기존과 바이트 동일).

### 3. 결정적 지연·사건 수명주기
- 해시: `shared/rng.ts` 문자열 키 해시, 목적별 키 분리(`report|eventId`, `detect|eventId|sensorId`, `miss|eventId|sensorId`). 새 RNG 스트림 없음, 센서 추가가 다른 표본을 바꾸지 않음.
- 신고 지연은 **교통량과 무관한 고정 분포**(ON/OFF 사이 결정론 보존). 센서 지연·미검지 확률은 종류별 파라미터. 오경보는 이번 범위 밖(후속).
- 게임 초 → tick은 `CLOCK_SCALE`·tick rate를 반영해 정수로 올림.
- 판정 위치: 확정된 장애물 위치(`placeObstacle` 결과)·건물 기준점. 곡선 차선의 다중 출입 구간 보존, 경계 포함 규칙 고정.
- 감지 후보는 사건 시작 시 결정(시뮬레이터 모드는 고정 도시 사본). 센서는 전원 필요: 예정 감지 tick에 그 위치가 정전이면 그 센서 무효(신고 후보는 유지).
- tick 내 순서: 만료 처리 → 예약 입력 → 도래한 인지 처리(정렬: detectTick, startTick, eventId) → 전력 갱신 → 응급·화재 → 우회 처리. 인지 전 종료·전소된 사건은 감지 큐에서 빼고 `missed`(사유) 기록. 사건당 인지 1회, 인지 전 출동·재출동 없음.

### 4. 센서 데이터·명령·버전
- `doc.sensors: Record<id, Sensor>`, `Sensor = { id, kind: 'cctv' | 'radar' | 'smartpole', segmentId, t, side, heading(도로 기준 상대 yaw), fov, range }` — **도로 부착형만**(MVP). 버스 정류장의 (segmentId, t, side) 연쇄 규칙을 그대로 따른다: 분할·필렛 시 t 재매핑(컷 구간 안이면 거절), 도로 삭제 시 함께 삭제. 자유 배치는 후속.
- 종류 기본값(보정 전 모의 값): CCTV(영상, 부채꼴), 레이더 검지기(좁고 긴 범위, 속도 저하로 사고 감지), 스마트폴(360° 짧은 범위). 감지 가능 사건: CCTV·스마트폴 = 사고·화재(외부 관측), 레이더 = 사고.
- 명령 `sensor.place / sensor.update(heading·fov·range·kind) / sensor.remove`, `LIMITS.sensors`, 검증(유한값·범위·ID 충돌), `docToCommands`·`docProblem`·`normalizeDoc`(`sensors ??= {}`)·가져오기·로컬 저장·서버 로그 재생 왕복.
- DOC_VERSION 7→8, PROTOCOL_VERSION 2→3(ADR 0012의 거절·새로고침 흐름 재사용). 구 서버는 v8 파일을 거부·보존.
- 시나리오 기록: `record.ts`의 정책 복사·검증·화이트리스트(`SCENARIO_PARAM_KEYS`)·엔진/시나리오 버전에 감지 설정 반영. 기존 기록은 `legacy`로 해석.

### 5. 센서 시각화·UX
- 센서 도구: 도로 가까이 커서 → 보도 위치 스냅, 기본 heading은 진행 방향(교차로 근처면 교차로 중심), **설치 전 부채꼴과 실제 커버되는 차선 구간 하이라이트 미리보기**, 드래그/휠로 방향 회전. 인스펙터에서 종류·FOV·범위 편집.
- 감시 범위 표시는 센서 도구 활성·센서 선택·레이어 토글 때만(평소엔 폴대 모델만). "건물 가림 미반영" 안내.
- `dirty`에 센서 도메인, 선택 윤곽·동료 고스트 연결. 센서 메시는 종류별 InstancedMesh.
- 시뮬레이터: 감지 순간 펄스·"CCTV 감지" 라벨, KPI — 감지 지연, 커버된 사건 비율, **미인지 사건 수·경과 시간**, 인지 전 종료·피해, 대응 시간 분해(감지+출동 대기+이동+처리), 감지 전 노출 차량 수.

### 6. 외관 — 1순위는 카메라와 바닥 맥락
- 진단(council 공통): 미니어처 인상 1순위 = **높은 시작 카메라 + 도시 바닥 맥락 부재(건물·도로 옆이 전부 균일한 잔디, 지평선 경계 선명)**. 축척 단서(가로수·가로등)는 그다음. 건물 창문·야간 점등·보도·차량 축척은 이미 구현돼 있음 → 중복 구현 금지, 튜닝만.
- P6c-1(빠른 개선): 자동 맞춤 카메라(실제 건물·도로 범위, 외곽 이상치 제한; **최초 방 입장 1회 + "도시 보기"·"눈높이 보기" 버튼에서만**, 협업 편집으로 시점이 튀지 않게), 안개 near/far 조정 + 하늘 그라디언트(`CityRenderer`의 낮/밤 배경 경로 함께 수정), 지면 격자 페이드를 안개와 맞추고 비편집 시 대비 낮춤, **블록·필지 포장면**(건물·도로 주변 콘크리트/포장, 공원·녹지만 잔디, 용도지역 색은 테두리·토글), 기존 건물 셰이더에 **접지 암부(밑단 3~4 m)·유리 하늘 반사 틴트**, 차량·신호·작은 소품 `castShadow=false`, 그림자 카메라를 보이는 범위에 맞춤, 톤·채도 미세 조정(ACES는 이미 사용).
- P6c-2(중간): 가로수·가로등은 도시 전체 단일 InstancedMesh 2~3개 + 셰이더 거리 페이드(드로 콜 +4 이내), 도로 확정 후 dirty 시점에만 재계산(드래그 중 재계산 금지). 건물 청크화는 측정 후 512~1024 m 대구역 또는 BatchedMesh — 인스턴스 속성 소유권(청크별)·ID→슬롯 매핑·dispose 설계 포함.
- P6c-3(후속): 원경 스카이라인 임포스터(배경임이 구분되게), 선택형 후처리(기본 꺼짐).
- 맵 크기(halfSize 2000) 유지.

### 7. 성능 예산·측정
- 기존 기준 유지(`apps/web/AGENTS.md`: 건물 2,000·차량 5,000, 데스크톱 60 fps·메인 드로 콜 < 150) + iGPU 장면 추가. 기존 통계(fps·드로 콜·삼각형)에 프레임 시간 p50/p95/p99, 그림자 패스 포함 여부, sim tick 시간, 편집 후 갱신 지연, 센서 커버리지 컴파일 시간을 추가. 같은 장면·카메라 경로·해상도·DPR로 전후 비교, 측정 중 자동 품질 고정. 품질 단계(낮음/보통/높음)는 sim 결과에 영향 없음.

## 순서
1. P6a(패널 스크롤·우클릭 회전·팔레트, 진행 중)
2. P6c-1 기준선 측정 → 빠른 개선 (P6a 이후, camera.ts 공유)
3. P6b-1 계약·sim(문서·명령 왕복 → 커버리지 → 감지 상태 머신 → 비교·KPI) — P6c-1과 병렬
4. P6b-2 센서 UI·시각화 (P6a 이후)
5. P6c-2 → (후속) P6c-3

## 기각
| 제안 | 이유 |
|---|---|
| 센서 0개 = 즉시 감지 | 설치하면 오히려 느려지는 역전(council) |
| 우회 큐 등록만 지연 | 신규 경로 탐색에 미인지 사고 정보 누출(council) |
| 신고 지연에 실시간 교통량 반영 | ON/OFF 사이 감지 시점이 달라져 비교 불공정 |
| 센서를 facilities 종류로 | 감시 기하(heading·fov)와 의미 불일치 |
| 월드 좌표 고정 센서(MVP) | 도로 편집 후 차로 위·허공에 남음 — 정류장 연쇄 규칙 재사용이 안전 |
| 창문 셰이더 신규 구현 | 이미 구현됨(buildingGeometry.ts) |
| 256 m 청크 × 타입 분할 | 드로 콜 폭증(청크 수 × 타입 수) |
| 건설 영역 확대 | 빈 초록 판만 커짐 |
