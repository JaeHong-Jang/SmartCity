# ADR 0014: Phase 7 — 도시·차량 현대화

- 상태: Accepted · 날짜: 2026-10-31 · 결정자: Opus (council: Astra, Argon — 둘 다 approve-with-changes)
- 제안서: `harness/runs/p7/proposal.md` · council: `harness/runs/p7/{astra,argon}.md` · 조사: [15 현대 도시 에셋](../research/15-modern-city-assets.md)

## 맥락
배포 사이트를 본 사용자: "너무 초라해 보여… 실제 현실처럼(국내 공공 3D 신도시 뷰어: 가로수 열·중앙분리대 녹지·붉은 벽돌 보도·유리 포디움·흰 고층 아파트·지평선 산)… 도시·차량 현대화부터". 건물 치수는 이미 실측 수준. council 공통 진단: 초라함 1순위 = **연속된 거리 요소(가로수·보도·분리대)와 시가지 밀도·단지 배치의 부재**, 그다음 파사드·지평선·상자형 차량. 자율주행 셔틀·중앙 관제 에이전트는 Phase 8.

## 결정
### 1. 에셋 — 절차 생성 (council 동의)
차량·건물·가로수·가로등·보도 모두 절차 생성(파일 0, 결정적, 인스턴싱). 외부 CC0 에셋은 이번에 도입하지 않음.

### 2. 거리 풍경 (렌더 전용, 문서·sim 불변)
- 가로수(수종 2~3: 은행·느티·벚 톤, 8~10 m 간격), 가로등(25~30 m, 밤 점등) — 결정적 배치, 교차로·횡단보도·정류장·센서·건물 앞 회피. 각 InstancedMesh 1~2개 + 거리별 LOD 분배·페이드.
- 무효화: 도로·정류장·센서·건물·필지 **확정 명령** 모두에서 영향 구간(256 m 청크 캐시)만 재계산. 드래그 중 재계산 금지. 카메라 LOD 분배는 별도 경로.
- 붉은 벽돌 보도: 도로 청크 셰이더의 월드 XZ 절차 패턴(드로 콜 +0).
- 격자: 배치 도구에서 **포장면 위에도 격자가 보이게**(격자를 포장 위 별도 얇은 패스 또는 포장 셰이더에 격자 합성), 스냅 간격 커서 하이라이트, 배경 격자와 스냅 표시 구분.

### 3. 지평선 산 (렌더 전용)
건설 영역 밖 저폴리 능선 2~3겹을 단일 메시(드로 +1). 원거리 대기 원근(안개색 쪽으로 색 보간)을 자체 셰이더로, 하늘·안개와의 지평선 일치 유지(P6c-1 픽셀 테스트 확장), 낮/밤 색.

### 4. 중앙분리대 도로 (계약 변경 — council blocker)
- 도로 타입 `median?: { width, planted }`. **생략 = 기존 도로 그대로**(기존 문서에 0 삽입 금지). width는 유한 양수·상한 검증, planted는 표현만.
- P7에서는 **`lanesForward === lanesBackward > 0`인 대칭 도로만** 허용. 차선 중심 `±(width/2 + (i+0.5)·laneWidth)`. "주행 가능 차도 폭"과 "보도 사이 전체 폭"을 구분하는 함수로 정리하고 모든 소비자(sim 차선·커넥터·횡단보도 충돌 영역·보행 그래프, 보도·노면 표시·센서·정류장·피킹, 건물 이격·필렛 최소 반경·자동 필지, roadNetwork fallback, 도로 타입 편집 UI)를 함께 변경.
- 교차로·횡단보도 구간은 분리대·식재를 끊고 횡단은 기존처럼 한 번에(중앙 대피섬·2단계 횡단·유턴 규칙 없음). 과속방지턱은 양쪽 주행 영역에만.
- 새 프리셋 "6차선 대로(중앙녹지)", "8차선 대로(중앙녹지)".
- **DOC_VERSION 8→9, PROTOCOL_VERSION 3→4 함께**(구 코드의 화이트리스트 복사가 median을 조용히 버리는 것 방지). 명령·체크포인트·가져오기·로컬 저장·워커·로그 재생 왕복.
- 골든: median 없는 도로의 기하·sim 결과·기존 기록 재생 바이트 불변(문서 전체 바이트는 버전 때문에 달라짐).

### 5. 건물 외관·프리셋
- 기존 파사드 셰이더 확장(커튼월·쇼윈도·하늘 반사 근사·옥상 녹화·설비는 이미 있음 — 튜닝): 한국식 고층 주거 외관(발코니 띠·측벽 세로 색 줄·옥탑 크라운 띠)을 **주거 고층 볼륨 규칙**으로(프리셋 ID 의존 없이 편집기 호환), 유리 반사는 반사 벡터 기반 하늘 그라디언트 근사(PMREM 기각).
- 새 프리셋(고층 아파트 판상 25F·타워 35F, 주상복합 타워, 유리 업무 포디움)은 **별도 ID, 기본 `growth` 없음**(기존 도시 성장 결과 불변). 기존 설계의 치수·용도는 보존. DOC 9 마이그레이션으로 추가.

### 6. 차량
- 절차 생성 둥근 차체·유리 캐빈·바퀴·전조등/후미등(밤 발광), 클래스별 LOD 3단계(인스턴스 버퍼 분배, ID·색·보간 유지), 차체+고정부를 단일 InstancedMesh로 합쳐 드로 콜 감소.
- 적용 규칙: 기본 차량 종류는 새 모델, 사용자 편집 차량(VehiclePart[])은 기존 부품 경로 유지(둥근 부품 옵션은 후속), 출동 소방·구급은 `emergency.ts`의 상자형 중복 차체를 새 모델로 교체. 물리 치수 불변.

### 7. 샘플 신도시 (council blocker 반영)
- 새 방에 생성. **단일 batch 한도(1,000 명령·512 KB) 안**에서 생성되도록 규모 산정 — 명령 수·UTF-8 바이트를 먼저 계산·테스트. 넘치면 규모를 줄인다(여러 batch·서버 생성 상태는 이번에 하지 않음).
- 생성 전 `growth` 끔(자동 성장이 끼어들지 않게), 한국형 남향 평행 단지·업무지구·상업 가로·공원·학교, 도로 연결성·건물 접근성·양방향 버스 경로 검사, 인구·일자리·차량 예산 표기. 완료 후 중심가 보기.

### 8. 성능
증분 목표(기준 도시: 삼각형 ≤ +0.5 M, 메인 드로 ≤ +45, iGPU 렌더 비용 악화 ≤ 15%)와 절대 목표(기존 < 150, 현재 171 초과 상태)를 구분해 보고. 5,000대 활성 교통·야간·카메라 이동을 추가 측정(미달은 명시). 품질 단계(낮음: 가로수·산 1겹·공격적 LOD).

## 순서
P7a 거리 풍경·산·격자(렌더) ∥ P7b 차량(렌더) ∥ P7c-1 계약(median·프리셋·DOC9/PROTOCOL4·sim 차선) + 건물 외관 → P7c-2 분리대 렌더(P7a의 roads.ts 이후) → P7d 샘플 신도시.
