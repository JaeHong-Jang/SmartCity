# ADR 0015: Phase 8 — AI City 에이전트 체계 (눈·두뇌·몸 + 중앙 관제)

- 상태: Accepted · 날짜: 2026-11-01 · 결정자: Opus (council: Astra approve-with-changes, Sol approve-with-changes — Argon 무응답으로 Sol 대체)
- 제안서: `harness/runs/p8/proposal.md` · council: `harness/runs/p8/{astra,sol}.md` · 조사: [16 AI City 에이전트](../research/16-ai-city-agents.md) · 팀 보고서 `보고서/work/report.md` 2장·4장

## 맥락
사용자: 자율주행 셔틀 하나가 아니라 다양한 AI 에이전트를 근거에 기반해 적용하는 실제 미래 도시. 에이전트 범위는 팀 보고서(눈–두뇌–몸, <표 1> 근거, 4.2 계획), 중앙 조율은 처음부터.

## 결정
### 1. 에이전트 목록 (보고서 기반)
A0 중앙 관제 · A1 영상 AI 감지(눈) · A2 차량 온디바이스(C-ITS·자율주행, 눈/몸) · A3 적응형 신호(두뇌) · A4 긴급 대응(두뇌) · A5 통제·우회 안내(두뇌/몸) · A6 디지털 트윈 사전 검증(두뇌) · A7 드론·로봇(몸) · A8 환경 지표(두뇌). 모두 sim 안의 **결정적 규칙/최적화 모듈**(입력·관측 시점·정렬·실행 예산·상태 수명주기 고정). LLM은 sim 밖 보조(결정 로그 요약 등)만 후속 검토.

### 2. 관제 계약: 관측 → 제안 → 중재 → 안전 실행 → 결과 (council blocker)
- **ObservationView**: 에이전트·관제가 보는 유일한 입력. **인지된 사건만**(ADR 0013 감지 모드), 일반 실시간 혼잡(속도·정지)은 허용, 미인지 사건·미래 입력 큐·평가용 실제 상태는 제외. 평가(KPI)는 실제 상태로.
- 에이전트는 공유 상태를 직접 바꾸지 않고 **제안**(요청 ID·유효기간·취소 가능)을 낸다. A0가 단계별 큐·안정 정렬 키·처리 상한으로 **중재**(생명 안전 > 확산 방지 > 흐름 효율, 결정적 tie-break), 채택된 것만 **안전 실행기**로.
- **신호는 단일 안전 상태 머신만 출력**한다. A0·A3·A4는 목표 위상만 요청하고, 황색·전적색·보행 정리·최대 대기·안전한 선점 복귀는 실행기가 보장. 적응형 모드에서는 WALK·스크램블 서비스와 최대 보행 대기를 계약으로 둔다(기존 선점 중 "새 WALK 없음"을 상시 제어에 쓰지 않음).
- 처음에는 **기존 tick 효과를 그대로 보존하는 어댑터**로 도입(같은 tick·같은 순서 → 골든·시뮬레이터 결과 불변).

### 3. 정책 정규화
- 대응 요인을 독립 변수로: `preempt`, `reroute`(정보 수신 차량 우회), `adaptive`, `battery`, `detection`, (후속) `drone`, `precheck`, `onboard`. **생략 = 기존 동작**(기존 `preempt`·`battery`가 `reroute`를 따르는 규칙 포함), 명시값의 범위·모순 정규화 규칙을 명시하고 record·화이트리스트·엔진 버전에 반영.
- 비교: 한 요인 비교 + **단계별 추가 실험(사다리)** — 우선신호만 → +우회 → +적응형 → 전체(보고서 2.2 가설), 감지·배터리·차량 구성 고정, 효과가 사라지는 조건도 보고.

### 4. 에이전트별
- A1: 물리 사건 입력과 **관측 보고 입력**(외부 영상 검지 결과 — 보고 지연·중복·종료 후 도착)을 분리(보고서 4.2).
- A2: 통신·수신·반응 지연(사람 vs 자율)과 운송 서비스(셔틀·로보택시)를 분리. 기존 정보 수신 해시 보존, 능력 배정은 목적별 별도 해시, 새 차종이 기본 수요 차종 비중을 바꾸지 않게. 차로 회피는 기존 차로 모델 한계 안에서(현장 복구 재사용).
- A3: 알고리즘 하나 선택(max-pressure 계열 또는 스케줄 기반 — 결정적), 하류 포화·기아 방지.
- A6: 현재 상태의 **정확한 분기**(완전 체크포인트) 또는 현재 tick까지 동일 정책 재생 후 분기 — 렌더 스냅샷·문서 복제 금지. 평가 순서: 안전 제약 → 실패·미도착 → 대응 시간 → 일반 지체, 무조치 후보 포함, 동률 규칙, 고정 연산 예산.
- A7: 신고로 출동하는 **확인 임무**와 독립 순찰 감지를 구분. 초기에는 선착·확인 시간만 기록, 지상 출동을 드론 확인 대기로 늦추지 않음. 로봇의 진압 효과는 근거 없음 → 효과 없이 시각화·시간 기록.
- A8: 지표만(조치 없음), "보정 전 모의 값".
### 5. 근거 표시
출처 유형(학술·기관 발표·보도·기업)과 성과 상태(실측·추정·목표·없음)·전이 한계(다른 도시·조건)를 분리 표기. 근거 없는 효과는 모델에 넣지 않음.
### 6. 로그·UI
감사 로그는 확정 결정·거절·취소만(반복 상태는 집계), 실행 길이·결정 수 상한과 초과 동작. 화면은 제한된 최근 목록. P8a의 AI 관제실은 에이전트 목록(눈·두뇌·몸 색)·결정 로그·선택 대상 지도 강조까지, 연결선·녹색 시간 막대·드론 등은 해당 기능 도입 시.
### 7. 적용 범위·버전
시뮬레이터 모드(도시 사본)에서 동작. 라이브 도시는 "실험에 사용할 에이전트 구성"만 표시(문서 저장 시 Command 경유·실험 시작 시 사본에 고정 — 도입 시 버전 결정). P8a는 문서 변경 없음.

## 순서
P8a 관제 틀(관측·제안·중재·안전 실행 어댑터) + 기존 감지·우선신호·우회를 에이전트로 편입(동작 불변) + 정책 정규화 + AI 관제실 최소 화면 → P8b 적응형 신호 + 관측 보고 입력 + 가설 사다리 실험 → P8c 차량 온디바이스·자율주행 셔틀/로보택시 → P8d 드론·로봇 → P8e 상태 분기·사전 검증 + 환경 → P8f 보고서 실험 프리셋(대전 트램형).
