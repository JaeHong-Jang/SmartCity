## 1. 목표와 범위

| 단계 | 내용 |
|---|---|
| **Phase 1 (MVP, 현재)** | 3D 도시 편집기: 카메라(줌·회전·이동), 도로(직선/곡선, 도로 타입 직접 정의, 교차로 자동 생성·분할), 건물(매스 블록을 조합하는 파라메트릭 에디터 + 배치), 차량 타입 에디터, 버스 노선, 신호 체계(자동 위상 + 편집), 도로 폐쇄, 교통 시뮬레이션(IDM + 예약 기반 교차로), **실시간 공동 건설**, 저장/불러오기 |
| Phase 2 | 지형(높이맵), 조닝·수요 모델, 차선 변경(MOBIL), 보호 좌회전, 감응 신호, 되돌리기/다시하기, 고가·터널 |
| Phase 3 | 서버 권위 시뮬레이션(모든 사용자가 같은 차량 상태를 봄), 돌발 상황(사고·재난·정전) 시나리오, 긴급차량 우선 신호, 적응형 신호, 도시 전체 대응 KPI |

## 2. 시스템 구성

```
┌──────────────── apps/web (브라우저) ───────────────────────────────┐
│ React HUD (도구 모음, 에디터 패널, 인스펙터, 접속자)                  │
│      │ dispatch(Command)                ▲ store 구독                │
│ ClientStore ──── Transport ─────────────┼──── WebSocket ────────┐  │
│   confirmed CityDoc                      │                       │  │
│      │ applied Command(seq)              │                       │  │
│      ├──────────► Sim Worker (packages/sim, 20Hz 고정 틱)         │  │
│      │              └─ snapshot(Float32Array, transferable) ──┐ │  │
│      ▼                                                         ▼ │  │
│ CityRenderer (Three.js): RoadMesh(병합) · Buildings(Instanced) ·   │  │
│                          Vehicles(Instanced, 틱 보간) · Signals    │  │
└───────────────────────────────────────────────────────────────────┼──┘
                                                                    │
┌──────────────── apps/server (Node) ──────────────────────────────┐│
│ Room: CityDoc + seq + clients  ◄── cmd ──────────────────────────┘│
│   applyCommand(doc, cmd) 성공 → seq++ → applied 브로드캐스트        │
│                           실패 → rejected (보낸 사람에게만)          │
│ Persistence: data/<room>.json (디바운스 저장)                       │
└───────────────────────────────────────────────────────────────────┘
```

### 패키지 경계
- **`packages/shared`**: `CityDoc` 스키마, `Command` 유니온, `applyCommand()`(트랜잭션/롤백), 네트워크 프로토콜, 시드 RNG, 기하 유틸(Vec2, 베지어, 폴리라인 오프셋), 편집 플래너(`planRoad` — 스냅·분할·교차 계산 → batch Command 생성).
- **`packages/sim`**: `CityDoc` → `RoadGraph` 컴파일(차선·커넥터·충돌표), 경로 탐색(차선 단위 A*), 차량(IDM), 교차로 관리자(신호 + 예약), 버스, 도로 폐쇄. DOM/Node API 없음 → 브라우저 워커와 서버 양쪽에서 실행 가능(Phase 3 대비).
- **`apps/server`**: 룸, 명령 시퀀싱, 검증, 프레즌스 중계, 영속화, 입력 제한.
- **`apps/web`**: 렌더링, 입력, 도구, 에디터 UI, 워커 브리지.

## 3. 핵심 결정 (ADR 후보)

### D1. 상태 변경 = Command 로그 (서버 순서 권위)
- 모든 변경은 직렬화 가능한 `Command`. `applyCommand(doc, cmd)`는 순수·결정적이며, 실패 시 문서를 변경하지 않는다(언두 로그로 롤백).
- 서버가 수신 순서대로 `seq`를 부여하고 적용 성공한 명령만 브로드캐스트. 클라이언트는 `seq` 순서로 적용 → 모든 참여자의 `CityDoc`이 동일.
- ID는 클라이언트가 생성(`<clientTag>_<counter>`)해 명령에 포함 → 왕복 없이 batch 안에서 새 엔티티 참조 가능, 적용은 여전히 결정적.
- **비낙관적 적용**: 클라이언트는 서버 에코를 받은 뒤에만 반영하고, 그 사이에는 고스트 프리뷰를 보여준다. 롤백 로직이 필요 없어 일관성이 단순하다. (낙관적 적용은 Phase 2)
- 서버가 없으면 `LocalTransport`가 브라우저 안에서 같은 역할을 해 단독 모드로 동작.
- CRDT(Yjs/Automerge) 기각: 도로 그래프의 참조 무결성(노드-세그먼트-신호)을 병합 결과가 보장하지 못함.

### D2. 도시 문서 모델 (`CityDoc`)
- 좌표: 미터 단위, XZ 평면(Y 위), 스냅 그리드 8m, 우측 통행(한국).
- `nodes` {id, pos} / `segments` {id, a, b, roadTypeId, control?(2차 베지어 제어점)} — 방향 forward = a→b.
- `roadTypes` (사용자 정의 가능): lanesForward, lanesBackward(0이면 일방통행), laneWidth, speedLimit, sidewalk, busOnlyRightLane.
- `buildingTypes` (사용자 정의): name, zone, **parts[]**(로컬 오프셋·폭·깊이·층수·층고·지붕형태·색) → 매스 블록 조합으로 ㄱ자, 포디움+타워 등 표현.
- `buildings` {id, typeId, pos, rotation}.
- `vehicleTypes` (사용자 정의): kind(car/bus/truck/emergency), 길이·폭·높이, maxSpeed, maxAccel, comfortDecel, color, spawnWeight.
- `intersections` {nodeId → control}: kind(signal/uncontrolled), phases?[{approaches: segmentId[], green}], yellow, allRed, offset. 항목이 없으면 degree≥3 노드는 자동 신호.
- `busStops` {segmentId, t, dir}, `busLines` {stopIds[], vehicleTypeId, buses, color}.
- `closures` {segmentId} — 돌발 상황 시뮬레이션의 첫 훅. Phase 3에서 `incidents`로 일반화.

### D3. 도로 편집
- 도로 도구는 시작점·(곡선이면 제어점)·끝점을 입력받고 `planRoad()`가 기존 노드 스냅(반경 6m) → 기존 세그먼트 위 스냅 시 **분할** → 새 도로가 기존 도로와 교차하면 교차점에서 양쪽 분할 → 결과를 하나의 `batch` Command로 만든다.
- 검증: 최소 세그먼트 길이 12m, 중복 세그먼트 금지, 너무 예리한 각(<15°) 경고.
- 교차로 메쉬: 연결된 도로 끝 단면 꼭짓점들의 볼록 다각형을 채움.

### D4. 교통 시뮬레이션
- **고정 틱 20Hz** (dt=0.05s), 시드 RNG → 결정적.
- **차선 그래프**: 세그먼트마다 방향·차선별 `Lane`(폴리라인, 누적 길이, 노드 setback만큼 양 끝 절단). 노드마다 진입 차선 → 진출 차선 `Connector`(3차 베지어). 회전 규칙: 최우측 차선 = 우회전+직진, 최좌측 = 좌회전+직진, 중간 = 직진, 1차선 = 전부. 막다른 길은 U턴 커넥터.
- **경로 탐색**: 차선/커넥터 그래프 A*, 비용 = 길이/제한속도 + 회전 페널티, 폐쇄 세그먼트 제외. 틱당 경로 계산 예산(기본 200건) 큐.
- **차량 운동**: 엣지(차선/커넥터) 위 1D 좌표 s, IDM 가속(δ=4), 탄도 적분. 선행 차량은 같은 엣지 → 경로상 다음 엣지들(최대 150m 전방)에서 탐색. 차선 변경 없음(경로가 차선을 결정).
- **교차로 관리자(예약 방식)**: 정지선 근처 차량이 진입 요청 → (신호가 해당 접근로에 녹색) ∧ (충돌 커넥터 점유/예약 없음) ∧ (진출 차선에 차체 길이 이상의 빈 공간 — 그리드락 방지)이면 허가. 요청은 도착 순서(FCFS)로 처리. 비허가 차량은 정지선을 가상 정지 선행차로 본다. 충돌표는 커넥터 폴리라인 교차 + 같은 진출 차선 합류로 미리 계산.
- **신호**: 위상(phase)은 접근로 묶음. 자동 위상 = 4지는 마주보는 접근로 쌍 2위상, 3지는 가장 마주보는 쌍 + 나머지, 5지 이상은 접근로별. 녹색 20s, 황색 3s, 전적색 2s. 좌회전은 예약 방식으로 비보호 처리(충돌 차량 없을 때만 진입).
- **수요**: 건물 존 기반 통행(주거 → 상업/업무/산업, 왕복). 건물이 없으면 임의 노드 간 통행. 밀도 슬라이더.
- **버스**: 정류장 순환 경로, 정차 10s, 노선당 대수 균등 배치.
- **네트워크 변경 시**: 그래프 재컴파일 → 기존 차선 ID가 유지되면 차량 유지 후 재탐색, 아니면 제거.

### D5. 렌더링·성능
- Three.js WebGLRenderer (WebGPU는 안정성 확인 후), 카메라 `camera-controls`.
- 도로: 네트워크 전체를 2개 병합 지오메트리(노면, 차선 표시)로 재생성 — 드로우콜 고정.
- 건물: 파트 형태별 `InstancedMesh`(박스, 박공지붕, 피라미드 지붕), 인스턴스 색. 수천 동도 드로우콜 수 개.
- 차량: kind별 `InstancedMesh`, 용량 2배씩 확장. 워커 스냅샷(Float32Array: x, z, heading, kind, colorIdx)을 Transferable로 받고 두 스냅샷 사이를 보간해 60fps.
- 선택/피킹: 메쉬 레이캐스트 대신 지면 평면 교차점 + 문서 공간 질의(공간 해시).
- 그림자: 품질 옵션.

### D6. 입력 UX (Cities: Skylines 관례)
- 좌클릭 = 도구 동작, 우클릭 드래그 = 이동, 휠 클릭 드래그 = 회전, 휠 = 커서 기준 줌.
- WASD/방향키 이동, Q/E 회전, R/F 줌, Esc 도구 해제, 1~9 도구 단축키.

### D7. 서버 보안·안정성
- 메시지 크기 제한 256KB, 클라이언트당 명령 속도 제한, 룸 ID 화이트리스트 정규식(`^[a-z0-9-]{1,32}$`, 경로 탈출 방지), 스키마 검증 실패 시 거부, 문서 엔티티 수 상한.

## 4. 테스트 전략
- shared: Command별 적용/거부/롤백, `planRoad` 스냅·분할·교차.
- sim: 그래프 컴파일, 경로(일방통행·폐쇄 반영), IDM 정지, 적색 정지/녹색 출발, **충돌 불변식**(장시간 실행 동안 같은 엣지 차량 간격 ≥ 0), **결정성**(같은 시드 → 같은 스냅샷 해시), 버스 정차.
- server: 두 클라이언트 동시 명령 순서·거부·영속화·룸 ID 검증.
- web: Playwright 스모크(로드, 도로 그리기, 차량 등장, 콘솔 에러 없음, 스크린샷).

## 6. 열린 질문 (v1, council 답변 완료 → 5절)
1. 비낙관적 적용(에코 대기)이 원격 협업 UX에서 수용 가능한가?
2. 차선 변경 없는 MVP가 4차선 도로에서 비현실적 정체를 만들지 않는가?
3. 교통 시뮬을 각 클라이언트 로컬에서 돌리는 Phase 1 → 서버 권위로 가는 전환 비용.
4. 렌더링: 네트워크 전체 단일 병합 지오메트리 재생성의 규모 한계(청크화 시점).
