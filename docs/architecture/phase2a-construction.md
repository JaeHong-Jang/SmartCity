# Phase 2a 설계안 — 건설 고도화 (조작 · 세분화 격자 · 필지 · 건물 스튜디오 · 도시 지표)

> 상태: Proposal (council 리뷰 대상) · 작성: Opus · 2026-10-23
> 근거: [`../research/03-grids-building-tools-survey.md`](../research/03-grids-building-tools-survey.md) (Sonnet), [`../research/04-urban-planning-smart-buildings.md`](../research/04-urban-planning-smart-buildings.md) (Sol)

## 사용자 요구
1. 클릭으로 움직일 수 있어야 한다 (카메라 + 배치한 객체).
2. 격자를 세분화해서 직접 설치할 수 있어야 한다.
3. 미래 스마트시티의 도시 구조를 실제로 설계하듯, 건물을 커스텀해서 만들 수 있어야 한다. 실제 시뮬레이션 게임처럼 고도화.

## 조사 결론 요약
- 시티빌더는 **기본 격자 + 정밀 모드 + 스냅 끔** 3단 스냅이 표준(Cities: Skylines Move It). 조닝 셀은 도로의 파생 데이터.
- 도시 구조 설계에는 **필지(폴리곤) + 용도지역 + 규제(건폐율·용적률·높이·후퇴)** 가 핵심 단위(국토계획법). 격자는 편집 도구일 뿐, 토지 경계와 동일시하면 사선 도로에서 계단형 필지가 생긴다(Sol 함정 #1).
- 건물은 **“격자로 편집하고 폴리곤으로 저장”**: 2m 기본·1m 정밀·4m 빠름. 층 묶음별 용도(복합용도), 외관은 스타일 규칙, 스마트 설비는 지붕/건물 속성(Sol §3–4).
- Townscaper식 불규칙 격자·복셀은 도시 구조 설계와 맞지 않아 기각(Sonnet §A).

## 범위 (이번 단계)

### A. 조작 — 선택 도구 확장
| 입력 | 동작 |
|---|---|
| 빈 땅 좌클릭 드래그 | 카메라 이동(팬) |
| 건물 좌클릭 드래그 | 건물 이동(현재 스냅 해상도 적용, 도로 침범·필지 위반 시 빨강). 놓을 때 `building.move` 1개 전송 |
| 선택된 건물: `[` `]` / Shift+휠 | 15° 회전 (Alt = 1°) |
| 교차점(노드) 좌클릭 드래그 | 노드 이동 → 연결 도로가 따라 변형. 놓을 때 `node.move` |
| 필지 꼭짓점 드래그 | 필지 형상 편집 |
| Delete / Backspace | 선택 객체 철거 |
드래그 중에는 로컬 미리보기만, 협업자에게는 프레즌스 고스트로 보인다(ADR 0001 비낙관적 적용 유지).

### B. 세분화 격자
- 스냅 해상도: **8m / 4m / 2m / 1m / 끔** — 하단 바 선택기 + `G` 순환. 격자 셰이더가 현재 해상도와 줌에 맞춰 표시.
- 도로 근처에서는 **도로 방향 로컬 격자**로 정렬(건물 정면이 도로를 향함).
- 격자 설정은 개인 UI 상태(문서에 저장하지 않음).

### C. 필지·용도지역 (도시 구조 설계 계층)
- 새 엔티티 `Parcel { id, polygon(Vec2[]), zone, regulation }`, 필지 도구로 격자 위에 사각형 드래그 또는 다각형 클릭.
- `zone`: 주거/상업/업무/공업/공공/녹지. 규제 프로필(게임 단순화): 건폐율, 용적률, 최고 높이, 도로 후퇴 거리 — 존별 기본값, 필지별 수정 가능.
- 건물이 필지 안에 있으면 **준수 검사**(건폐율·용적률·높이·필지 이탈) → 인스펙터·오버레이에 위반 표시. 막지 않고 경고(설계 탐색 허용).
- 필지 오버레이: 존 색상 반투명 면 + 경계선.
- 도로 기반 자동 블록·필지 분할은 후속(Sol §2 OBB 분할).

### D. 건물 스튜디오 (커스텀 건물 설계)
- 전용 3D 편집 화면(오버레이): 궤도 카메라, **1m/2m/4m 편집 격자**, 대지 경계 표시.
- 건물 = **볼륨(매스) 목록**. 볼륨마다:
  - 평면: 격자 셀 브러시(칠하기/지우기, 드래그 사각형) → **직교 폴리곤**으로 저장 (`footprint`)
  - 시작 높이(아래 볼륨 위에 쌓기), 층수, 층고 — 높이 핸들 드래그로 푸시/풀
  - **용도**(주거/상업/업무/공업/공공) → 복합용도 건물(저층 상가 + 상층 주거)
  - 외관 스타일: 격자창 / 띠창 / 커튼월 / 무창, 창 비율, 1층(상점/로비/필로티), 벽·지붕 색, 지붕 형태
- 건물 단위 **스마트 설비**: 태양광 지붕(지붕 면적 비율), 녹색지붕, EV 충전기 수, IoT 센서, 옥상 드론 포트 — 같은 지붕 면적을 태양광·녹화·드론포트가 나눠 쓰는 **면적 예산 검사**(Sol 함정 “설비 보너스 중복”).
- 실시간 지표: 연면적, 건축면적, 높이, 거주 인구/일자리, 에너지 수요, 태양광 발전, 탄소.
- 미래형 프리셋: 친환경 타워(녹화 테라스+태양광), 주상복합, 스마트 오피스, 데이터센터, 수직농장, 모빌리티 허브, 학교, 병원.
- 설계 변경 시 같은 설계를 쓰는 건물 전체가 바뀐다는 것을 UI에 명시하고, **“복제해서 새 설계로”** 를 제공(Sol 함정 “암묵적 공유”).

### E. 도시 지표 (시뮬레이션 게임 루프의 시작)
- 순수 함수 `cityStats(doc)` (shared): 인구, 일자리(용도별), **RCI 수요**(인구 대비 일자리·상업 공간 균형), 에너지 수요/자가발전, 탄소(건물 전력 + 교통 VKT), 녹지·녹색지붕 비율, 필지 규제 위반 수.
- 상단 도시 대시보드 + 정보 뷰 오버레이(용도지역, 규제 위반).
- 통행 수요는 건물 용도별 연면적 기반으로 갱신(복합용도 반영).

## 계약 변경 (packages/shared)
```ts
interface BuildingPart {            // 기존 필드 유지 (하위 호환)
  ...
  footprint?: Vec2[];               // 로컬 직교 폴리곤(반시계). 있으면 width/depth 대신 사용
  use?: Zone;                        // 볼륨 용도 (없으면 BuildingType.zone)
  facade?: { style: 'grid'|'ribbon'|'curtain'|'none'; windowRatio: number; ground: 'none'|'shop'|'lobby'|'pilotis' };
}
interface BuildingType { ...; smart?: { solarRoof: number; greenRoof: number; evChargers: number; sensors: boolean; dronePort: boolean } }
interface Parcel { id; polygon: Vec2[]; zone: Zone | 'green'; regulation: { coverage: number; far: number; maxHeight: number; setback: number } }
Command += building.move{id,pos,rotation} | parcel.upsert{parcel} | parcel.remove{id}
shared: footprintArea(), partArea(), buildingMetrics(type) (연면적·용도별 면적·높이·지붕 면적), cityStats(doc), parcelCompliance(doc, parcel)
```
기존 방(room)의 문서는 새 필드가 없어도 그대로 동작해야 한다.

## 기각/후속
- 도로 부착 조닝 셀 + 자동 성장(서버 결정적 틱 필요) → Phase 2b
- 되돌리기/다시하기(역명령, 도로 batch 역연산에 `segment.merge` 필요) → Phase 2b
- 다중 선택·박스 선택, 모듈 키트(벽·창·발코니), 중정(구멍 있는 폴리곤), 자유각 평면 → 후속
- 필지 자동 분할(OBB), 일조 사선, 지역 조례 → 후속

## council에 묻는 것
1. 범위 A–E가 한 단계로 과한가? 빼거나 미룰 것.
2. 필지를 “경고만” 하는 규제 모델이 설계 도구로 맞는가, 아니면 배치를 막아야 하는가.
3. 건물 평면을 폴리곤으로 저장(셀은 편집 전용)하는 결정 — 협업·렌더링 관점의 위험.
4. 건물 렌더링: 폴리곤 압출 볼륨을 **설계(타입)별 병합 지오메트리 + 인스턴싱**으로 바꿀 때 성능/드로우콜 위험.
