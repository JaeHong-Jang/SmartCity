## 사용자 요구
1. **건물 만들기가 너무 어렵다.** 사람들이 창의적으로 만들 수 있어야 한다. 3D 건물 제작 게임과 웹 도구를 참고한다.
2. **사람이 보여야 한다.** 집에서 나와 움직이고, 실제로 이동하는 모습이 보여야 한다.
3. **차량 쪽 교통 요소를 다 갖춘다.** 횡단보도, 과속방지턱 등 교통 관련 요소가 모두 있어야 한다.

## A. 건물 스튜디오 (3D 블록 쌓기)

### 조사 결론
쉽고 창의적인 도구에는 공통점이 있다.
- 3D에서 직접 조작한다.
- 고스트 미리보기를 보여준다(가능 = 초록, 불가 = 빨강).
- 스냅 격자가 결과물의 품질을 보장한다.
- 세부는 규칙이 자동으로 정한다.
- 고정 팔레트를 쓴다.
- 대칭 기능이 있다.
- 프리셋이나 주사위(무작위 생성)로 시작할 수 있다.
- 부담 없이 되돌릴 수 있다.

참고 사례는 다음과 같다.
- **Townscaper, Minecraft:** 클릭해서 쌓는다.
- **Sims 빌드 모드:** 지붕과 마감이 자동으로 정해진다.
- **SketchUp:** 푸시/풀 편집.
- **three.js `webgl_interactive_voxelpainter` (MIT):** 면 법선 방향으로 스냅하고, Shift로 삭제한다.

### 결정안

**편집 표현과 저장**
- 편집 단위는 **2m × 2m × 1층** 셀(복셀)이다. 4m 큰 브러시를 함께 제공한다.
- 편집 상한: 평면 32 × 32 셀, 30층, 점유 셀 4,000개.
- 저장할 때는 셀을 **기존 `BuildingPart`(직교 다각형 볼륨)로 변환**한다. 서버 계약(구멍 없음, 꼭짓점 ≤ 32, 볼륨 체적 겹침 금지)은 그대로다.
- 다시 열 때는 파츠를 셀로 역변환한다. 2m 격자에 맞지 않는 구 설계는 스냅된다는 경고를 띄우고, 숫자 입력 에디터를 "정밀 모드"로 남겨 둔다.
- 셀 원본은 저장하지 않는다(ADR 0007 §5 유지).

**변환 알고리즘** (`packages/shared/src/editing/voxels.ts`, 순수·결정적)
1. 층 k마다, 같은 스타일 키(벽색·지붕색·파사드·용도)를 가진 점유 셀을 4-이웃 연결 성분으로 나눈다.
2. 위아래로 연속된 층에서 셀 집합과 스타일 키가 같으면 하나의 파츠로 합친다(`floors = n`, `baseHeight = k × floorHeight`).
3. 성분에 구멍이 있거나 꼭짓점이 32개를 넘으면, 중앙 행이나 열을 따라 재귀적으로 이등분해 구멍 없는 조각으로 나눈다. 절단 방향은 긴 축을 우선한다.
4. **파츠 상한을 16에서 48로 올린다.** 셀 단위로 칠한 색이 파츠 분할 원인이 되므로, UI에 파츠 예산 게이지를 둔다.
5. 지붕은 기본이 평지붕이다. 사각형 최상층 파츠에만 박공·피라미드를 고를 수 있다.

**장식 부품 (prop)**
```ts
type PropKind = 'balcony' | 'awning' | 'sign' | 'ac' | 'antenna' | 'waterTank' | 'chimney'
              | 'planter' | 'tree' | 'flag' | 'solarPanel' | 'helipad' | 'canopy' | 'bench';
interface BuildingProp {
  kind: PropKind;
  /** 건물 로컬 좌표(m), y = 부착 높이 */
  pos: { x: number; y: number; z: number };
  /** 90° 단위 회전 0..3 (벽 부착 prop은 바깥 방향) */
  rot: 0 | 1 | 2 | 3;
  /** 폭 배수 1..4 */
  size: number;
  color: string;
}
BuildingType.props?: BuildingProp[]   // ≤ 64
```
- 서버 검증: kind enum, 유한한 좌표, 파츠 외곽 bbox ± 2m 안, y ∈ [0, 최고 높이 + 6].
- prop은 건폐율·면적 지표와 도로 침범 판정에 넣지 않는다. 벽에서 1.5m 이하로만 돌출하고, 그 정도는 후퇴 거리가 흡수한다.
- 렌더는 설계별로 구운 지오메트리에 프리미티브(박스·원기둥·삼각기둥) 조합으로 합친다. 인스턴싱 구조는 그대로다.

**스튜디오 UI** (`apps/web/src/ui/studio/*`, 전용 three.js 캔버스)
- **도구:** 쌓기(면 클릭 → 인접 셀 추가, 지면 드래그 → 사각 채우기, 위로 드래그 → 층 올리기), 지우기(우클릭 또는 Shift), 칠하기(셀 또는 연결 덩어리), prop 붙이기(면에 스냅), 스포이드.
- **보조:** 현재 층 슬라이더(위층 반투명), 대칭 X/Z, 로컬 Undo/Redo, 주사위.
  - 주사위는 시드 기반 형상 문법이다: 기단 → 본체 → 후퇴 → 지붕 → prop.
  - 스타일은 주택, 상가, 유리 오피스, 친환경 타워, 한옥풍 등이다.
- **팔레트:** 고정 팔레트(벽 12, 지붕 6, 포인트 6). 재질 프리셋은 기존 파사드 셰이더 조합으로 만든다(벽돌 주택, 유리 커튼월, 상가 1층 등).
- **실시간 지표:** 기존 MetricsPanel을 재사용한다. 저장은 변환 → `preflight` → `buildingType.upsert{expectedRev}` 순서다(기존 충돌 감지 유지).
- 기존 프리셋 8종과 기존 설계를 스튜디오로 열 수 있다.

## B. 거리 교통 시설

### 데이터 (doc v3)
```ts
type RoadFeatureKind = 'crosswalk' | 'speedBump' | 'schoolZone';
interface RoadFeature {
  id: string;
  segmentId: SegmentId;
  kind: RoadFeatureKind;
  /** 구간 비율(0..1, a→b 호 길이). schoolZone은 구간 전체라 무시 */
  t: number;
  /** crosswalk 전용: 보행 신호 유무 */
  signal?: boolean;
}
CityDoc.features: Record<string, RoadFeature>
IntersectionControl.kind: 'signal' | 'uncontrolled' | 'allStop'
IntersectionControl.crosswalks?: boolean   // 교차로 자동 횡단보도, 기본 true(보도 있는 차수 ≥ 3 노드)
Command += feature.upsert{feature} | feature.remove{id}
```
- **검증:**
  - 점 시설은 구간 끝에서 12m 이상, 서로 6m 이상 떨어져야 한다.
  - 횡단보도는 보도가 있는 도로 타입에만 놓을 수 있다.
  - schoolZone은 구간당 하나다.
- **분할과 삭제:** `segment.split`은 버스 정류장처럼 t를 다시 매핑하고, 끝에 너무 가까워진 시설은 제거한다. `segment.remove`는 시설도 함께 제거한다.

### sim 동작
| 시설 | 차량 | 보행자 |
|---|---|---|
| 교차로 횡단보도 | 정지선을 횡단보도 폭만큼 뒤로 물린다(차선 trim). 커넥터가 횡단보도 다각형과 교차하면 충돌 관계로 등록한다. 횡단보도가 점유되었거나 보행자가 claim한 경우 해당 커넥터 grant를 거부한다(우·좌회전 양보). | 보행 신호(신호 교차로) 또는 claim 후 충돌 커넥터 holder가 0이 되면 진입한다. |
| 구간 횡단보도 | 횡단보도가 차단 상태이면 그 앞을 가상 정지선으로 삼는다. 이미 제동 거리 안에 들어온 차량은 그대로 통과한다. | 신호형은 고정 주기이고, 비신호형은 claim → 커밋 차량이 빠지면 진입한다. |
| 과속방지턱 | 통과 목표 속도 20km/h(5.6m/s)에 맞춰 IDM 상한을 감속 곡선으로 깎는다. 커브 감속과 같은 방식이다. | — |
| 어린이보호구역 | 구간 차선 제한속도를 min(기존, 30km/h)으로 둔다. | — |
| 모든 방향 일시정지 | 정지선에서 완전히 멈춘 뒤에야 grant를 요청한다(선착순). | — |

- **기아 처리:** Sol의 권고를 따른다. 비신호 횡단보도에서 차량을 강제로 통과시키지 않는다. 차량 대기시간 통계를 노출하고, 혼잡한 곳에는 신호 설치를 권고 배지로 띄운다. 보행자는 같은 횡단보도에 이미 건너는 무리가 있을 때만 합류한다. 무리가 비면 대기 차량이 먼저 간다.
- **보행 신호:** 다리 L의 횡단보도는 다음 두 조건을 모두 만족할 때 보행 녹색이다.
  - L이 녹색 접근로가 아니다.
  - 녹색 접근로에서 L로 들어가는 직진 커넥터가 없다.

  위상 녹색의 끝부분 `횡단 길이 / 1.0 m/s` 동안은 점멸이고, 점멸 중에는 새로 진입하지 않는다.

## C. 시민 생활 (보행자 + 하루 일과), Sol 06 반영
- **보행 그래프 (`PedGraph`)**
  - 차량 `Lane/Connector`와 분리된 별도 타입으로, 같은 최종 setback에서 파생한다.
  - 에지 종류는 보도(차도 끝 + 보도 폭/2), 모서리(인접 다리 보도 경계를 miter/bevel로 연결, 교차로 중심 통과 금지), 횡단보도, 출입구다.
  - 출입구는 도로를 향한 외곽면 중점이다. access 에지는 차도를 가로지르지 못한다. 보도 방향은 차량 일방통행과 무관하게 양방향이다.
- **보행 이동**
  - 경로를 추종하고 **방향별 보행 띠**(0.65m, 보도마다 진행 방향 오른쪽 띠)를 쓴다.
  - 같은 띠 안에서 최소 0.7m 간격을 지키고, 에지 전이 시 입구 공간을 확인한다.
  - 선호 속도는 `clamp(1.3 + 0.5(r1 − r2), 0.8, 1.8)` m/s로 한 번 뽑는다.
  - 걷기 애니메이션 위상은 누적 보행 거리에서 계산한다.
- **시민 (지속 개체, sim 런타임 상태이며 문서에 넣지 않음)**
  - 인구는 `stats.ts` 계수(주거 30m²/인 등)로 정하고, 정수 인구는 최대 나머지법으로 배분한다.
  - 상한은 8,000명이다. 넘으면 비율로 샘플링하고 시민마다 `represents` 가중을 둔다.
  - 직장은 남은 일자리 정원에 비례해 추첨한다.
  - 상태: AtHome → Leaving → Walking / Driving / WaitingBus / RidingBus → Entering → AtWork / AtShop → …
  - 활동은 틱 이벤트 큐로 처리한다(전 인구 순회 없음).
  - 일과: 출근 07~09시 분산, 근무 8시간, 귀가 전 상점 30%(15~45분).
  - 수단: 보행 경로 ≤ 600m이면 도보. 그 이상이면 버스(직통, 정류장 300m 이내)와 자가용을 예상 시간으로 비교한다. 차량 보유는 시민별 시드로 정한다.
  - **자가용 연결:** 출입구 → 도보 → 차량 스폰 → 도착 → 하차 → 도보 → 출입구 순서로 이어진다. 차량에 personId가 붙는다.
  - **수요 일원화:** 시민이 있으면 기존 확률 수요는 배경 통과 교통으로 축소한다(trafficDensity × 0.25). 건물이 없는 도시는 기존 방식이다.
  - **버스 승하차:** 정류장 대기열(도착 틱, id), 정원 40, 하차 후 승차, 정차시간은 `max(10, 1 × 하차 + 1.5 × 승차)`초다. 정류장 순서로 목적 정류장을 확인한다.
- **시계 (게임 결정)**
  - 하루 시각은 `06:30 + 틱 시간 × 10`이다(실제 1초 = 게임 10초, 하루 = 2.4시간, 4배속이면 36분).
  - Sol은 물리시간과 같은 축(배율 1)을 권고했다. 하지만 하루를 실제 24시간 동안 볼 수 없어서 Cities: Skylines처럼 **달력 압축 모드**를 택한다.
  - 활동 체류시간은 게임 시각 기준이고 이동은 물리 시간이다. 이 비대칭을 ADR에 명시하고, 통행시간 통계는 물리 초로 표기한다.
- **집 안 활동 표현:** 건물별 재실 인원을 집계해 창문 점등에 쓴다. 출입구 앞에서 1초간 출입 동작을 보여준다. 이는 실내 활동의 시각적 요약이며 실내 이동이 아니다.
- **보행 신호와 횡단 예약**
  - 보행 신호는 `WALK(7초) → CLEARANCE(⌈L / 1.0⌉초, 신규 진입 금지) → RED`다. 해당 차량 위상의 녹색은 `max(green, walk + clearance)`로 연장한다.
  - 횡단은 차량과 보행자가 공유하는 **충돌 구역(ConflictZone)의 원자적 예약**으로 처리한다.
    - 차량은 커넥터 grant(또는 구간 중간 내부 정지선 통과 허가) 시점에, 경로상 충돌 구역(진입 다리와 진출 다리)이 비어 있고 진입 대기 보행자가 없으면 함께 예약한다. 해제는 차량 후미 기준이다.
    - 보행자는 허가(WALK 또는 비신호) 상태에서 차량 예약이 0이면 구역과 건너편 수용 공간을 한 번에 예약한다. 해제는 몸체가 이탈한 뒤다.
    - 보호구역 안 비신호 횡단보도에서는 차량이 보행자 유무와 관계없이 STOP한다.
- **스냅샷 확장**
  - `pedestrians: Float32Array`, stride 8 = x, z, heading, speed, gaitPhase, style, state, elevation
  - `pedestrianIds: Uint32Array`
  - `crossings: Float32Array`, stride 6 = x, z, heading, width, 보행신호(0 red / 1 clearance / 2 walk / 3 비신호), 점유
  - `occupancy: Float32Array`(건물 id 정렬 순서), `buildingIds`
  - `stats.clock{dayTime, day}`와 `stats.citizens{total, home, work, walking, driving, bus}`
  - 반환 버퍼 풀과 transfer 목록도 확장한다.
- **틱 순서 (Sol §8)**
  1. 명령·재컴파일
  2. 신호 + 보행 허가
  3. 활동 이벤트 + 승하차
  4. 경로 예산(차량과 보행 공통, 작업 수 기준)
  5. 요청 수집
  6. 원자적 예약(차량 grant + 보행 횡단)
  7. 가속·보행 이동량
  8. 적분·전이
  9. 해제·도착
- **재컴파일:** 보행자가 있던 에지가 사라지면 가장 가까운 보도로 재접속하고 경로를 재계획한다. 실패하면 집으로 순간 귀가 처리하고 사유를 집계한다. 예약은 일괄 정리한다.
- **성능 목표 (미검증):** 차량 3천 대 + 실외 보행자 5천 명에서 step p95 < 4ms. bench 테스트로 측정한다.

## D. 렌더링 (07 반영)
- **보행자:** 절차적 박스 사람 1개 InstancedMesh로 그린다. `aLimb` 속성 + 정점 셰이더로 팔다리를 흔들고, 옷 색은 무작위다. 그림자는 끄고, id 기준으로 보간한다.
- **노면:** 도로 청크 메시에 지브라 횡단보도, 물린 정지선, 방지턱(쐐기 + 황흑 사선), 보호구역 적색 노면을 추가한다. `segSig`에 시설을 포함한다. 표시 위치의 출처는 sim·문서 데이터다.
- **보행 신호등:** 횡단보도 양끝에 2구 신호등을 둔다.
- **낮밤:** 시계로 태양 각도·색·하늘을 바꾸고, 건물 셰이더 `uNight`로 창문을 발광시킨다. 창문 점등은 재실 인원 비율을 따른다(집에 사람이 돌아오면 불이 켜진다). 가로등은 발광 램프만 둔다.
- **HUD:** 시계(07:32 · 1일차)와 시민 현황(외출, 보행, 출근 중)을 보여준다.
