# Review: Phase 2b — shared 계약 + 건물 스튜디오
> 리뷰어: Sol · 관점: Research · Analysis · Verification  
> 기준: ADR 0008 §1·§2, 작업 트리의 Phase 2b 변경 및 신규 파일. 파일 수정 없음.

## 판정: reject

원본 설계의 무경고 변경과, 서버가 승인한 문서를 다시 명령으로 가져오지 못하는 반례가 확인됐다.

### 실행 근거

요청한 기본 명령은 설정 로딩 중 실패했다.

```text
npx vitest run packages/shared apps/web/src/studio
Error: EROFS: read-only file system
... node_modules/.vite-temp/vitest.config.ts.timestamp-....mjs
```

파일 쓰기가 필요 없는 설정 로더로 재실행했다.

```text
npx vitest run packages/shared apps/web/src/studio --configLoader runner

Test Files  7 passed (7)
     Tests  105 passed (105)
  Duration  4.11s
```

추가 검증은 esbuild의 `write:false`로 메모리에서 번들한 실제 함수를 실행했다.

- 4×4 단층 격자의 비어 있지 않은 **65,535가지 배치**를 변환하고 서버 검증했다. 구멍·꼭짓점·볼륨 겹침으로 거절되는 반례는 발견하지 못했다.
- **48파츠 × 32꼭짓점 + 64 prop**인 유효 입력은 승인됐다. 5회 검증 시간은 **21.20 / 5.34 / 4.50 / 4.67 / 2.75ms**였다. 모든 기하 배치의 최악 시간을 보장하는 측정은 아니다.
- 시설·보호구역·교차로 제어가 있는 문서에서, 분할 후 실패하는 batch의 **롤백 전후 deep equality**를 확인했다.
- 시설 ID `__proto__`, `constructor`, `prototype`은 거절됐다. 확인한 null·누락 필드·NaN·Infinity 입력에서는 호출 밖으로 예외가 전파되지 않았다.
- WebGL 실브라우저 조작, 최대 크기 설계의 메모리 사용, 연결 단절·지연 응답의 UI 통합 시나리오는 **미검증**이다. 테스트 통과를 해당 항목의 검증으로 간주하지 않았다.

## 동의하는 점 (짧게)

- prop 저장 시 허용 필드만 복사하며, 종류·회전·개수·좌표를 서버에서 검사한다.
- 시설 연쇄 삭제, 보도 제거 시 횡단보도 정리, 보호구역 분할 상속과 `crosswalkLegs` 교체가 구현돼 있다.
- 저장 응답을 요청 ref로 식별하고 저장 시점의 편집 버전을 기록해, 늦은 응답이 이후 편집을 저장 완료로 표시하지 않도록 구성했다.
