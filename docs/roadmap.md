### Phase 1 잔여 과제
- 실제 GPU에서 성능 측정 (목표: 차량 5,000 + 건물 2,000에서 60fps) — 헤드리스 SwiftShader로는 측정 불가
- 버스 노선 오버레이를 sim 실제 경로로 표시, 자동 위상일 때도 위상 화살표 표시
- 오프라인 폴백 후 서버 재연결 시 자동 온라인 전환
- 이름 변경 시 재접속 없이 반영(프로토콜에 rename 메시지)
- 협업 e2e 간헐 실패 1회 관찰(동시 부하 상황, 재현 실패) — 추적 중

## Phase 2b — 생활과 거리 (완료, [ADR 0008](adr/0008-phase2b-life-streets-studio.md))
- [x] 3D 건물 스튜디오: 블록 쌓기·사각 채우기·층 핸들·덩어리 칠하기·장식 14종·대칭·Undo·주사위 5종·템플릿, 셀→볼륨 변환(파츠 48), 손실·크기 검사
- [x] 교통 시설: 교차로 자동 횡단보도(다리별), 구간 횡단보도(신호/비신호), 과속방지턱, 어린이보호구역, 모든 방향 일시정지
- [x] 차량·보행자 충돌 구역 원자 예약, 보행 신호(WALK·점멸), 비신호 12초 게이트, 재컴파일 시 점유 복구
- [x] 시민: 보행 그래프(보도·모서리·횡단·출입구), 방향별 보행 띠, 하루 일과(출근·상점·귀가), 도보/자가용 연결, 인원 보존
- [x] 렌더: 절차적 보행자(걷기 애니메이션), 지브라·방지턱·보호구역 노면, 보행 신호등, 낮밤 시계·재실 창문 점등
- 측정: 차량 3천 + 보행자 5천(Node) step+snapshot p95 약 7~11ms(목표 4ms 미달), 재컴파일 틱 약 350ms(워커)

## Phase 3b·3c — 버스 승객·보행 전용 신호·조닝 성장·AI 건설 도우미 (완료, [ADR 0009](adr/0009-phase3bc-transit-zoning-ai.md))
- [x] 버스: 정류장 노드·FIFO 대기열·정원(기본 40)·승하차 정차 시간(10~40s)·대기 한도 30분, 모든 정리 경로에서 시민 단일 소유, 도보/버스/자가용 수단 선택(노선 없으면 기존 규칙과 동일), busLoad·정류장 대기 스냅샷
- [x] 보행 전용(스크램블) 위상: 차량 전적색 + 모든 다리 동시 보행, 차량 위상 WALK 없음, 교차로 인스펙터 체크박스·주기 표시
- [x] 조닝 도구(9)·도로변 8m 셀 lot·auto 필지/건물, 서버 GrowthDirector·오프라인 성장, RCI 수요 HUD·자동 성장 토글, 도로 편집 시 auto 필지 정리·적색 예고
- [x] AI 건설 도우미: Claude API 도구 루프(서버 키), 도시 사본에서 설계·배치·조닝 제안 → 다중 고스트 미리보기 → 사용자 승인 적용, 충돌 항목 부분 적용, 서버 전체·IP·룸 비용 상한
- 미룸: 대각선 횡단보도, 성장 레벨업·쇠퇴, 환승, 버스 창문 점등, AI 철거·도로 변경, 차량 인스펙터

## Phase 3 — 돌발 상황 대응 시뮬레이션
- 서버 권위 시뮬레이션: `(seq, effectiveTick)` 명령 적용, 체크포인트(차량·RNG) 직렬화, `WebSocketSimStream`
- `incidents` 레이어: 사고(차선 차단·지속시간), 공사, 재난(구역 폐쇄), 정전(신호 소등 → 비신호 운영)
- 대응 주체: 긴급차량 출동·우선 신호(황색·전적색 보장), 우회 안내, 적응형 신호(Max-Pressure)
- 시나리오 스크립트(명령 시퀀스 + 타이밍) 재생, KPI(통행시간, 대응시간, 정체 길이, 제거 차량 수) 대시보드
- 보정·검증: 실제 교통량 데이터와 비교 (현실 예측 주장 전 필수)
